# 操作とモード

ToraNeko.Mk3 の機体の操作、LED の表し方、モードの割り当てをまとめたものです。2026-10-14 に作者と話し合って決めました。2026-10-15 に、残っていた LED の表示と操作の細かいところ（起動、電池、走行中、走り終わり、保存中、出力中、センサ値の表示、吸引 ON、最短走行の道の確かめ、最初のターンの置き場所）を決めました。
作るのはステップ9（`sys/mode.c`、`sys/ui.c`、`sys/goal.c`、`sys/explore.c`、`sys/flash.c`、`drv/flash_memory.c`）です。KOGUMA との違いの細かいところは [KOGUMA_PORTING.md](KOGUMA_PORTING.md) にあります。

## 1. 使う部品

ToraNeko にはブザーがないので、合図はすべて LED で出します。

| 部品 | 使い方 |
|---|---|
| 左タイヤ | モードを選ぶ（KOGUMA と同じ） |
| 右タイヤ | No. を選ぶ（KOGUMA と同じ）。ゴールの x・y を入れる |
| スイッチ SW1 | 決定。スタート待ちのときに押すと、選び直しに戻る。フェイルセーフで止まったときに押すと、元に戻る |
| 前センサ | 手をかざして、手を離すとスタート |
| LED 7 個 | モードと No. の表示、合図 |

## 2. 操作の流れ

1. 電源を入れる。「ロード中」（LED1→7 と 1 個ずつ点けて消す、約 1 秒）が出て、モード0 の No.0（何も選んでいない状態）になる。迷路は空、ゴールは Flash から読む
   - 電池が少ないときは、外側の 4 個（LED1・2・6・7）が 0.5 秒ごとに点滅し続け、何もできない。電池を替えて電源を入れ直す（電池を調べるのは電源を入れたときだけ。KOGUMA と同じ）
2. 左タイヤを回してモード、右タイヤを回して No. を選ぶ
   - 1 段ぶんにタイヤを回す量は、実機で決める（ToraNeko のタイヤは 14mm で KOGUMA より小さい）
   - モードは 7 の次が 0、No. は 15 の次が 0 に戻る（一周する。一周するのは KOGUMA と同じだが、KOGUMA はモードも 0〜15）
3. スイッチを押して決定する。LED が 7 個全部 1 回点滅し、スタート待ちになる
   - スタート待ちのあいだにスイッチを押すと、「ロード中」を出して 2 に戻る（間違えて決定しても、電源を切らずに済む）
   - 最短走行（モード1）は、決定したときにスタートからゴールへの道があるかを調べる。なければ「できなかった」の合図を出して 2 に戻る（機体を置いて手をかざす前にわかる。KOGUMA はスタートしてから調べる）
   - センサ値の表示（モード5 No.1）と壁までの距離の表示（No.3）は、スタート待ちをせずにすぐ始まる（前センサの値を見たいので、手で始めない）。スイッチを押すと終わり、「ロード中」を出して 2 に戻る
4. 機体をスタート区画に置き、前センサに手をかざす。LED が 7 個全部点く
5. 手を離す。LED が全部消え、1 秒後に走り出す
   - この 1 秒で、ジャイロの 0 点を測る（手が触れた揺れがおさまってから測れる）
   - 手を離してから走り出すので、手を「前の壁」と読むことがない
6. 走り終わると、「うまくいった」の合図（7 個全部を 1 秒）を出し、「ロード中」を出してから、**同じモード・No. のまま** 2 に戻る（同じテストや最短走行を続けて走らせやすい。KOGUMA はモード0 No.0 に戻る）
   - 探索でスタートに戻ったとき・片道でゴールに着いたときは、先に迷路を Flash に保存する（外側の 4 個が点いているあいだ、約 1〜2 秒）
   - 持ち上げたときにタイヤが回って番号がずれることがあるので、スイッチを押す前に LED を確かめる
7. 2 に戻るときは、どこから戻るときも（スタート待ちの取り消し、センサ値の表示の終わり、走り終わり、フェイルセーフの解除）「ロード中」を出す。このあいだはスイッチを押しても何も起きないので、続けて押したスイッチが次の決定にならない（2026-10-22 に決定）

出力と設定（モード7）も、走るモードと同じ流れで始める（スイッチで決定 → 前センサに手をかざす）。

## 3. LED の表し方

モードは真ん中の 3 個、No. は外側の 4 個で、どちらも 2 進数で表す（KOGUMA と同じ表し方）。基板の LED の並びに合わせた。

```
上から見た図（上が機体の前）

          LED3  LED4  LED5          ← モード（4・2・1）
   SW
   LED1  LED2        LED6  LED7     ← No.（8・4・2・1）

例：モード5 → LED3 と LED5 が点く（4 + 1）
    No.6   → LED2 と LED6 が点く（4 + 2）
```

| 場面 | LED |
|---|---|
| 電源を入れたとき | 「ロード中」を出してから、モード0 No.0 の表示（全部消えている）になる |
| 電池が少ないとき（電源を入れたときに調べる） | 外側の 4 個（LED1・2・6・7）を 0.5 秒ごとに点滅させ続ける。何もできない（KOGUMA は 7 個全部を点滅。ToraNeko ではフェイルセーフと見分けるために外側だけにした） |
| モードと No. を選んでいるとき | 選んでいるモードと No. を点けたまま |
| スイッチで決定したとき | 7 個全部が 1 回点滅 |
| スタート待ち | 選んだモードと No. を点滅（選んでいるときと区別する） |
| 前センサに手をかざしたとき | 7 個全部が点く |
| 手を離したとき | 全部消える（1 秒後に走り出す） |
| 走っているとき | 壁制御で使っている壁を出す：左の壁を使っていれば LED1・2、右の壁を使っていれば LED6・7（KOGUMA と同じ。壁制御がうまく効いているかが、走っている姿で見える） |
| 走り終わったとき（探索でスタートに戻った、片道・最短走行でゴールに着いた、ターンの調整などが終わった） | 「うまくいった」と同じ（7 個全部を 1 秒） |
| Flash に保存しているあいだ（迷路・ゴール） | 外側の 4 個を点けておき、終わったら消す（約 1〜2 秒。CPU が止まるので、点けたままにしかできない。このあいだに電源を切ると保存が残らない） |
| ログ出力のあいだ（モード7 No.1。走行ログがいっぱいだと約 10 秒） | 「ロード中」を繰り返す。終わったら「うまくいった」 |
| センサ値の表示・壁までの距離の表示（モード5 No.1・3） | 壁の有無を出す：左の壁 LED1・2、前の壁 LED3・4・5、右の壁 LED6・7（機体の向きと LED の並びがそろう） |
| センサ値の記録で測っているあいだ（モード5 No.2。1 秒） | 真ん中の 3 個（LED3・4・5）を点けたまま。終わったら「うまくいった」 |
| 吸引 ON で吸っているあいだ（モード6 No.3） | 真ん中の 3 個（LED3・4・5）を 0.5 秒ごとに点滅 |
| フェイルセーフで止まったとき | 7 個全部を点滅させる。スイッチを押すと「ロード中」を出してから元に戻る（KOGUMA は全部を点けて、前センサに手をかざすと戻る） |
| ロード中（電源を入れたとき、モード選択（2）に戻るとき（フェイルセーフの解除も含む）。ログ出力のあいだは繰り返す） | LED1 から LED7 へ 1 個ずつ順に点けていき（左下 → 上 → 右下）、7 個全部が点いたら消す（約 1 秒）。このあいだはスイッチを押しても何も起きない（続けて押したときに、次の決定にならないように） |
| うまくいった（ゴールを保存した、迷路を呼び出せた、走り終わった、ログ出力が終わった） | 7 個全部を 1 秒点ける |
| できなかった（ゴールがスタートの区画を含む、保存した迷路がない、探索で道がなくなった（行き・帰りのどちらでも）、最短走行でゴールへの道がない） | 外側の 4 個（LED1・2・6・7）を速く 5 回点滅させる |

- 点滅の速さ：決定のときの全部の点滅は 0.15 秒ごと、スタート待ちの点滅は 0.25 秒ごと、フェイルセーフの全部の点滅・電池が少ないときの外側の点滅・吸引中の真ん中の点滅は 0.5 秒ごと、「できなかった」は 0.08 秒ごと、ロード中は 1 個 0.15 秒
- 外側の 4 個だけの表示は 3 つあり、点き方で見分ける：点けたまま＝保存中、0.5 秒ごとに点滅し続ける＝電池が少ない、速く 5 回点滅＝できなかった。ただし、モード0 の No.15 を選んでいるときも外側の 4 個が点けたままになる（保存中と同じ見た目。保存は走り終わったときとゴールを入れたときだけなので、場面で見分ける）
- 2026-10-15 に変更：フェイルセーフで止まったときは、全部を点けたままにする代わりに点滅させ、前センサに手をかざす代わりにスイッチで元に戻すようにした。戻るときに「ロード中」を出す
- 入力の読み方：0.01 秒ごとに読む。スイッチは 2 回続けて同じ値を読んだら押した（離した）とみなす（チャタリングを取り除く）。前センサの手は 3 回続けて同じ値を読んだら、かざした（離した）とみなす
- タイヤ 1 段ぶんの回す量は、今は仮に 8192 カウント（タイヤ半回転。`sys/ui.h` の `UI_TIRE_COUNT_PER_STEP`）。実機で決め直す
- モードを選び始めるときに、それまでにタイヤが回った量を忘れる（走っているあいだに回った量で、モードや No. が変わらないように）
- 作ったもの：`sys/ui.c`（LED と入力）、`sys/mode.c`（モードを選んで走らせる）、`sys/goal.c`（ゴールの位置）。PC テスト（`test/test_mode.c`）済み

## 4. モードの割り当て

| モード | 中身 | KOGUMA のモード |
|---|---|---|
| 0 | 探索 | モード0 |
| 1 | 最短走行 | モード1、モード3 No.1〜3 |
| 2 | 探索のターン調整 | モード4 No.2・3・6 |
| 3 | 最短走行のターン調整 | モード5〜10 |
| 4 | 実験用（機体の性能を測る、試しに走らせる。中身は必要に応じて自由に入れ替える） | （ない） |
| 5 | センサ（値の表示と調整） | モード4 No.0、モード3 No.4〜9 |
| 6 | 基本調整 | モード4 No.1、4、5、6、モード6 No.0 |
| 7 | 出力と設定 | モード4 No.7（設定は KOGUMA にはない） |

**どのモードも No.0 は何もしない**（間違えて決定しても何も起きないように。電源を入れた直後はモード0 の No.0）。表にない番号も何もしない。No.0 や表にない番号では、スイッチを押しても決定しない（点滅もしない）。

今 `sys/mode.c` にあるのは、モード0 の No.1〜3（探索）、モード1 の No.1〜3（最短走行。今は小回りだけ）、モード2 の No.1・2・4・5（スラローム 90°、U ターン、その場 180° 旋回、壁合わせだけ）、モード3 の No.1〜7（最短走行のターン）、モード5 の No.1〜3（センサ値の表示・記録、壁までの距離の表示）、モード6 の No.1（直進）・No.6（エンコーダの歪みを測る）・No.7（壁に沿って直進）と、モード7 の No.1・2・15（ログ出力、ゴールの位置、迷路呼び出し）。ほかのモードは、中身（最短走行、ターン、センサなど）を作ったときに足す。

### モード0：探索

探索はすべて**吸引なし**のスラローム探索。

| No. | 走り方 | KOGUMA |
|---|---|---|
| 1 | 往復（スタート → ゴール → スタート） | No.1 |
| 2 | 片道（ゴールで止まる） | No.3 |
| 3 | 未知壁探索。ゴールに着いたら、最短経路の上のまだ見ていない壁を見に行く。見に行く壁がなくなったら、止まらずにスタートへ戻る（流れは [KOGUMA_PORTING.md](KOGUMA_PORTING.md) の「ToraNeko の未知壁探索の流れ」） | No.6（KOGUMA は吸引あり） |

- 探索は、今ある迷路の続きから始める（KOGUMA と同じ）。最初からやり直したいときは、電源を入れ直す
- 作らないもの：吸引ありの探索、全面探索、探索のあとに続けて最短走行を走る（KOGUMA の `SHORTEST`）
- 既知区間加速（見たことのある区間を速く走る）は、今は使わない。経路を作る `path_make_known` は残しておき、使うときは No.4 に「未知壁探索＋既知区間加速」を足す
- 探索の速さ（KOGUMA は 500mm/s）は実機で決める
- 止まるのは、U ターン（止まって、その場で 180° 回って発進する）、未知壁探索で計算するとき、終わり（スタートに戻ったとき、片道でゴールに着いたとき）。終わりは、その区画の真ん中で止まる（スタートでも、後ろの壁に当てる動きはしない）
- 作ったもの：`sys/explore.c`（PC テスト済み。機体を動かす部分の中身はステップ7 で作る）

### モード1：最短走行

- 経路はダイクストラで作る
- **No. は遅い順**。No.1 がいちばん遅く、確実に完走する速さ。大会では 1 → 2 → 3 と上げていく
- 各 No. は速度の表の 1 行で、中身は「ターンの速さ（組 1〜3 のどれか。モード3 のターン調整と同じ組）、直線の最高速、加速度、斜めの加速度、吸引の強さ」
- 「直線の最高速 ＝ ターンの速さ」の行（区間ごとの加減速がない、デバッグ用。KOGUMA のモード3 No.1〜3）も、この表の行として入れる
- 行の数と中身（数値）は実機で決める
- スイッチで決定したときに、スタートからゴールへの道があるかを調べる。なければ「できなかった」を出して、モードを選び直す（走らない）
- ゴールに着いたら止まり、モーターと吸引を止めて「うまくいった」を出す。スタートへは手で戻す（KOGUMA と同じ）
- 走行ログは 8ms おきで 8 秒ぶん。8 秒を超えたら記録をやめるだけで、走行は続ける
- ターンごとに通過速度を変える方式（KOGUMA の TurnV）は、KOGUMA の実機の結果を見てから決める。使うなら、この表に行を足す

**今あるもの**（2026-10-25 に作った。中身は `sys/shortest.c`。実機はまだ）

大回りと斜めの動きは、まだ実機で合わせていないので、**曲がるところは探索と同じ小回りのスラローム（300mm/s）だけ**にした。直進だけ、No. ごとに速くする。
経路はダイクストラで探し、コストは「この No. の速さで小回りで走る時間」にする（2026-10-27。KOGUMA の #99 の走行時間の表を持ち込んだ。`maze/dijkstra.c`）。小回りのジグザグは 300mm/s のままなので、直進を長く・曲がる回数を少なくした道が選ばれる（壁のない迷路で (7,7) へ行くとき、曲がる回数が 13 回から 1 回になった。PC のテスト）。

| No. | 直進の最高速 | 直進の加速度 |
|---|---|---|
| 1 | 300mm/s（探索と同じ。道を確かめる） | 1000mm/s² |
| 2 | 600mm/s | 2000mm/s² |
| 3 | 1000mm/s | 3000mm/s² |

- 値は `config/run_params.h` の SHORTEST1〜3
- 迷路は RAM のものを使う。探索のあと電源を切ったときは、先にモード7 No.15（迷路呼び出し）で Flash から戻す
- スタート区画では、探索と同じく、お尻を後ろの壁に付けて置く
- 横の壁に沿って走る補正を入れる。吸引はまだない
- 走行ログは 8ms ごと（モード7 No.1 で出す）

### モード2：探索のターン調整

探索で使う動きを、探索の速さで 1 つずつ走らせて調整する。曲がるのは**左だけ**（KOGUMA と同じ）。

| No. | 動き |
|---|---|
| 1 | スラローム 90°（探索の小回り。曲がる前・後の距離も合わせる） |
| 2 | U ターン（減速して止まり、その場で左に 90° を 2 回回って発進する。回る前と、1 回目の 90° のあとに、前に壁があれば前壁合わせをする。行き止まりで使う） |
| 3 | 止まって発進（区画の真ん中で止まり、前壁合わせをして、その場で左に向きを変えて発進する。未知壁探索で計算するときに使う） |
| 4 | その場 180° 旋回だけ（U ターンの部品。KOGUMA のモード4 No.2） |
| 5 | 壁合わせだけ（U ターンの部品。KOGUMA のモード4 No.6） |

- No.4・5 は基本調整（KOGUMA のモード4）から移したもの。U ターンがうまくいかないときに、部品ごとに確かめる。壁合わせは、基本調整（モード6 No.4）にも入れてある（どちらも同じ処理を呼ぶ）
- スラローム 90°（No.1）：区画のまん中に置いて始める（左の区画をあけておく）。次の区画の入口まで 300mm/s に速くしながら進み、前距離 4.6mm → 左に 90°（最高 600deg/s、8000deg/s²）→ 後距離 4.7mm で左の区画の入口へ、そこから 45mm で止まる。左の区画のまん中で、左を向いて止まれば合っている。前距離・後距離は PC の計算の値（2026-10-24 に実機で、左の区画のまん中で止まった）。曲がり終わったあとの角度と距離は、モード7 No.1 で出す。走行ログは 2ms ごと（2026-10-24 に追加。中身は `sys/adjust.c`）
- U ターン（No.2）：区画のまん中に置き、前の区画が行き止まりになるようにして始める。前の区画のまん中で止まり、前壁合わせ（0.5 秒）→ 左に 90° → 前壁合わせ → 左に 90°、元の区画のまん中まで戻って止まる（2026-10-24 に、180° 1 回から 90° 2 回に変えた。行き止まりなら、横の壁でも合わせられる）。探索の U ターンと同じ動き（`ctrl/run.c`）。走行ログは 3ms ごと（2026-10-24 に追加）
- 壁合わせだけ（No.5）：区画のまん中に、前に壁がある向きで置いて始める。前の壁で位置と向きを 0.5 秒直して止まる。少し斜めに・前後にずらして置いて、直るかを見る。目標は、3 枚とも壁ありの区画のまん中で、センサ値の記録（モード5 No.2）で測った前センサの値（左前 3244・右前 3240。2026-10-24）。走行ログは 1ms ごと（2026-10-24 に追加）
- その場 180° 旋回（No.4）：左に 180° を、最高 720deg/s・角加速度 7200deg/s² で回って止まる（KOGUMA は 2000deg/s・50000deg/s²。まずゆっくり）。止まったら、ジャイロで測った角度と、前後に動いてしまった距離を覚えておき、モード7 No.1 で出す。走行ログは 1ms ごと（2026-10-23 に追加。中身は `sys/adjust.c`）
- スタートに戻ったときの動き（後ろの壁に当てる）は入れない
- 走行ログは 1ms おきで 1 秒ぶん

### モード3：最短走行のターン調整

最短走行で使うターンを 1 つずつ走らせて調整する。No. でターンの種類を選ぶ（KOGUMA と同じ番号）。曲がるのは**左だけ**（KOGUMA と同じ）。

| No. | ターン |
|---|---|
| 1 | 大回り 90° |
| 2 | 大回り 180° |
| 3 | 斜め入り 45° |
| 4 | 斜め入り 135° |
| 5 | 斜め出 45° |
| 6 | 斜め出 135° |
| 7 | V90° |
| 8 | スタートからの大回り 90°（最短走行の最初のターン） |
| 9 | スタートからの斜め入り 45°（同上） |

**壁までの距離の表示（No.3）の使い方**（2026-10-27 に追加。中身は `sys/sensor_view.c`）

**壁までの距離の表の作り方**（2026-10-27 に決めた。表は `ctrl/wall_dist.c`。今入っているのは計算で作った仮の表）

距離は、区画のまん中でどれも 42mm（区画 90mm から壁の厚さ 6mm を引いて 2 で割る）。
- 横（L・R）：機体の中心線から横の壁の表面まで。機体の幅は 40mm（メイン基板。タイヤ・センサホルダも基板の内側）なので、中心線から側面まで 20mm
- 前（FL・FR）：タイヤの軸から前の壁の表面まで。軸から基板の前の端まで 32mm

1. ビューアを開き、「保存先フォルダ」で `logs/` を選んで「接続」する（[logs/README.md](logs/README.md)）
2. 下の距離に機体を置き（壁とまっすぐ平行に）、No.2（センサ値の記録）で測る
3. ビューアの「メモ」に `R 64mm` のように **センサの名前（R・L・F）と距離** を書き、モード7 No.1 で出す。`logs/` に `日時_sensor_R-64mm.txt` で保存される
4. 全部測ったら、`software/main-controller/` で `python3 tools/wall_table.py logs/*_sensor_*.txt` を実行する。出た行を `ctrl/wall_dist.c` の同じ名前の行と置きかえる（同じ距離を何回か測ったときは平均する。距離が遠いのに値が大きいところがあれば「注意」が出る）
5. 書き込んで、No.3 で、ものさしで測った距離と合うかを確かめる

| 測るもの | 置き方 | 距離 [mm] |
|---|---|---|
| 右（`R`） | 左右に壁がある区画で、機体の左の側面を左の壁に付ける（右の壁まで 64mm）。左の壁と機体のあいだに壁の板（6mm）を 1 枚ずつはさむ | 64・58・52・46・40・34・28・22（板 0〜7 枚） |
| 左（`L`） | 右の左右を入れかえる | 同上 |
| 前（`F`。左前と右前を同時に） | 前の壁と、基板の前の端とのすきま g をものさしで測って置く（距離 = 32 + g）。お尻を後ろの壁に付けて板をはさむなら、距離 = 52 − 6 × 枚数 | 32・37・42・52・62・72・87・102・122・142 |

区画の入口で前の壁を見るときの距離は約 87mm なので、そのまわりは正確に測る。

**ゴールの入れ方**（No.2）

ゴールは「左下の区画の位置（x・y）」だけを機体で入れる。大きさは **2×2 で決まり**で、機体では設定しない（コードの定数。違う大きさの大会では、書き換えて書き込み直す）。

1. 7 個全部が 1 回点滅して、x の入力になる
2. 右タイヤを回して値を選ぶ。1 段で 1 ずつ変わる。最初は今のゴールの値

## 5. 迷路の保存と呼び出し

KOGUMA は迷路を RAM にしか持たない（電源を切ると消える）。ToraNeko は Flash にも保存する。

| 場面 | 迷路 |
|---|---|
| 電源を入れたとき | 空。Flash の迷路は自動では読まない |
| モード7 No.15（迷路呼び出し） | Flash の迷路を RAM に戻す（電池を替えたあとに、続きから最短走行・探索をするとき） |
| 探索を始めるとき | RAM の迷路の続きから |
| Flash に保存するとき | ・探索でスタートに戻ったとき<br>・片道でゴールに止まったとき<br>・フェイルセーフで止まったとき（下） |
| 未知壁探索の途中で止まったとき | 保存しない（止まっている時間を延ばさないため。ぶつかったときは、フェイルセーフの保存で残る） |
| 探索で道がなくなって止まったとき（行き・帰りのどちらでも。動きすぎたときも同じ） | 保存しない（壁を読み間違えたかもしれないため。RAM の迷路には残っている。止まる途中でぶつかったときは、フェイルセーフとして扱う） |
| フェイルセーフで止まったとき | 最後に壁を記録した **5 回ぶん**（ふつうは 5 区画。U ターンで同じ区画に 2 回入ると、その区画は 2 回と数える）を、記録する前の状態に戻してから保存する（その走行で初めて入った区画なら「まだ見ていない」に戻る。前の走行で見ていた区画なら、そのときの状態に戻る）。RAM の迷路も同じように戻すので、電源を切らずに探索をやり直しても、ずれた状態で読んだかもしれない壁は使わない |

- 「迷路を消す」操作は作らない。電源を入れ直せば RAM の迷路は空になる。Flash の古い迷路は、次に保存したときに上書きされ、迷路呼び出しを選ばなければ使われない
- Flash に書き込んでいるあいだは、CPU が止まる（STM32F411 は Flash が 1 つで、消しているあいだはプログラムを読めない。128KB の区画を消すのに約 1〜2 秒）。そのため、保存はモーターを止めているときだけにする
- 「最後の 5 区画ぶんを戻す」ために、`maze/maze_map.c` に「壁を記録した区画を、記録する前の状態と一緒に 5 回ぶん覚えておき、戻す」機能を足した（`maze_map_undo_recent_cells`。PC テスト済み）

**保存のしかた**（`sys/flash.c`、`drv/flash_memory.c`。2026-10-15 に作った）

| 項目 | 内容 |
|---|---|
| 保存場所 | Flash のいちばん後ろの 2 つのセクタ（128KB ずつ）。ゴールはセクタ6（0x08040000〜）、迷路はセクタ7（0x08060000〜）。別のセクタなので、片方を保存しても、もう片方は消えない |
| プログラムの大きさ | 保存場所と重ならないように、前の 256KB（セクタ0〜5）に収める（今は約 42KB）。超えたら CI（firmware-build の「サイズ」）が失敗にする |
| 書く中身 | ゴール：目印、x、y、確かめの数（4 語）。迷路：目印、迷路の大きさ、区画ごとに 4 枚の壁の状態と「入ったか」、確かめの数（5123 語、約 20KB） |
| 壊れていないかの確かめ | 「目印」で保存したことがあるかを、「確かめの数」（それまでに書いた数の合計）で途中で電源が切れていないかを調べる。どちらかが合わなければ読まない（迷路の呼び出しは「できなかった」の合図になり、ゴールは基準のゴール (7, 7) になる） |
| 迷路を呼び出すとき | 全部を読んで確かめてから迷路に入れる（途中まで入れて、おかしな迷路になることはない）。「最後に壁を記録した 5 区画」は忘れる（読み込む前の迷路のものなので） |
| プログラムを書き込み直したとき | ふつうに書き込むと、プログラムが入るセクタだけが消されるので、保存した迷路とゴールは残る。書き込みツールで「全部消す（Full chip erase）」をすると消える |
