# 操作とモード

ToraNeko.Mk3 の機体の操作、LED の表し方、モードの割り当てをまとめたものです。2026-10-14 に作者と話し合って決めました。2026-10-15 に、残っていた LED の表示と操作の細かいところ（起動、電池、走行中、走り終わり、保存中、出力中、センサ値の表示、吸引 ON、最短走行の道の確かめ、最初のターンの置き場所）を決めました。
作るのはステップ9（`sys/mode.c`、`sys/ui.c`、`sys/goal.c`、`sys/explore.c`、`sys/flash.c`、`drv/flash_memory.c`）です。KOGUMA との違いの細かいところは [KOGUMA_PORTING.md](KOGUMA_PORTING.md) にあります。

## 1. 使う部品

ToraNeko にはブザーがないので、合図はすべて LED で出します。

| 部品 | 使い方 |
|---|---|
| 左タイヤ | モードを選ぶ（KOGUMA と同じ） |
| 右タイヤ | No. を選ぶ（KOGUMA と同じ）。ゴールの x・y を入れる |
| スイッチ SW1 | 決定。スタート待ちのときに押すと、選び直しに戻る。フェイルセーフで止まったときに押すと、元に戻る |
| 前センサ | 手をかざして、手を離すとスタート |
| LED 7 個 | モードと No. の表示、合図 |

## 2. 操作の流れ

1. 電源を入れる。「ロード中」（LED1→7 と 1 個ずつ点けて消す、約 1 秒）が出て、モード0 の No.0（何も選んでいない状態）になる。迷路は空、ゴールは Flash から読む
   - 電池が少ないときは、外側の 4 個（LED1・2・6・7）が 0.5 秒ごとに点滅し続け、何もできない。電池を替えて電源を入れ直す（電池を調べるのは電源を入れたときだけ。KOGUMA と同じ）
2. 左タイヤを回してモード、右タイヤを回して No. を選ぶ
   - 1 段ぶんにタイヤを回す量は、実機で決める（ToraNeko のタイヤは 14mm で KOGUMA より小さい）
   - モードは 7 の次が 0、No. は 15 の次が 0 に戻る（一周する。一周するのは KOGUMA と同じだが、KOGUMA はモードも 0〜15）
3. スイッチを押して決定する。LED が 7 個全部 1 回点滅し、スタート待ちになる
   - スタート待ちのあいだにスイッチを**短く**押して離すと、「ロード中」を出して 2 に戻る（間違えて決定しても、電源を切らずに済む）
   - スタート待ちのあいだにスイッチを **1 秒以上押し続ける**と、手をかざすかわりにスタートする（2026-11-02 に足した）。1 秒たつと 7 個全部が点き、スイッチを離すと消えて、1 秒後に走り出す。区画のまん中で前に壁があると、前センサは壁を見ていて（壁まで約 10mm）、手をかざして離したのがわからないので、そのときに使う（壁合わせだけ（モード2 No.5）、センサ値の記録（モード5 No.2）など）
   - 最短走行（モード1）は、決定したときにスタートからゴールへの道があるかを調べる。なければ「できなかった」の合図を出して 2 に戻る（機体を置いて手をかざす前にわかる。KOGUMA はスタートしてから調べる）
   - センサ値の表示（モード5 No.1）と壁までの距離の表示（No.3）は、スタート待ちをせずにすぐ始まる（前センサの値を見たいので、手で始めない）。スイッチを押すと終わり、「ロード中」を出して 2 に戻る
4. 機体をスタート区画に置き、前センサに手をかざす。LED が 7 個全部点く
5. 手を離す。LED が全部消え、1 秒後に走り出す
   - この 1 秒で、ジャイロの 0 点を測る（手が触れた揺れがおさまってから測れる）
   - 手を離してから走り出すので、手を「前の壁」と読むことがない
6. 走り終わると、「うまくいった」の合図（7 個全部を 1 秒）を出し、「ロード中」を出してから、**同じモード・No. のまま** 2 に戻る（同じテストや最短走行を続けて走らせやすい。KOGUMA はモード0 No.0 に戻る）
   - 探索でスタートに戻ったとき・片道でゴールに着いたときは、先に迷路を Flash に保存する（外側の 4 個が点いているあいだ、約 1〜2 秒）
   - 持ち上げたときにタイヤが回って番号がずれることがあるので、スイッチを押す前に LED を確かめる
7. 2 に戻るときは、どこから戻るときも（スタート待ちの取り消し、センサ値の表示の終わり、走り終わり、フェイルセーフの解除）「ロード中」を出す。このあいだはスイッチを押しても何も起きないので、続けて押したスイッチが次の決定にならない（2026-10-22 に決定）

出力と設定（モード7）も、走るモードと同じ流れで始める（スイッチで決定 → 前センサに手をかざす）。

## 3. LED の表し方

モードは真ん中の 3 個、No. は外側の 4 個で、どちらも 2 進数で表す（KOGUMA と同じ表し方）。基板の LED の並びに合わせた。

```
上から見た図（上が機体の前）

          LED3  LED4  LED5          ← モード（4・2・1）
   SW
   LED1  LED2        LED6  LED7     ← No.（8・4・2・1）

例：モード5 → LED3 と LED5 が点く（4 + 1）
    No.6   → LED2 と LED6 が点く（4 + 2）
```

| 場面 | LED |
|---|---|
| 電源を入れたとき | 「ロード中」を出してから、モード0 No.0 の表示（全部消えている）になる |
| 電池が少ないとき（電源を入れたときに調べる） | 外側の 4 個（LED1・2・6・7）を 0.5 秒ごとに点滅させ続ける。何もできない（KOGUMA は 7 個全部を点滅。ToraNeko ではフェイルセーフと見分けるために外側だけにした） |
| モードと No. を選んでいるとき | 選んでいるモードと No. を点けたまま |
| スイッチで決定したとき | 7 個全部が 1 回点滅 |
| スタート待ち | 選んだモードと No. を点滅（選んでいるときと区別する） |
| 前センサに手をかざしたとき | 7 個全部が点く |
| 手を離したとき | 全部消える（1 秒後に走り出す） |
| 走っているとき | 壁制御で使っている壁を出す：左の壁を使っていれば LED1・2、右の壁を使っていれば LED6・7（KOGUMA と同じ。壁制御がうまく効いているかが、走っている姿で見える） |
| 走り終わったとき（探索でスタートに戻った、片道・最短走行でゴールに着いた、ターンの調整などが終わった） | 「うまくいった」と同じ（7 個全部を 1 秒） |
| Flash に保存しているあいだ（迷路・ゴール） | 外側の 4 個を点けておき、終わったら消す（約 1〜2 秒。CPU が止まるので、点けたままにしかできない。このあいだに電源を切ると保存が残らない） |
| ログ出力のあいだ（モード7 No.1。走行ログがいっぱいだと約 10 秒） | 「ロード中」を繰り返す。終わったら「うまくいった」 |
| センサ値の表示・壁までの距離の表示（モード5 No.1・3） | 壁の有無を出す：左の壁 LED1・2、前の壁 LED3・4・5、右の壁 LED6・7（機体の向きと LED の並びがそろう） |
| センサ値の記録で測っているあいだ（モード5 No.2。1 秒） | 真ん中の 3 個（LED3・4・5）を点けたまま。終わったら「うまくいった」 |
| 吸引 ON で吸っているあいだ（モード6 No.3） | 真ん中の 3 個（LED3・4・5）を 0.5 秒ごとに点滅 |
| 吸引の力のテストで回しているあいだ（モード4 No.3） | いまの段を、LED1 から順に段の数だけ点ける（1 個 = 1.0V … 5 個 = 5.0V）。終わったら「うまくいった」 |
| フェイルセーフで止まったとき | 7 個全部を点滅させる。スイッチを押すと「ロード中」を出してから元に戻る（KOGUMA は全部を点けて、前センサに手をかざすと戻る） |
| ロード中（電源を入れたとき、モード選択（2）に戻るとき（フェイルセーフの解除も含む）。ログ出力のあいだは繰り返す） | LED1 から LED7 へ 1 個ずつ順に点けていき（左下 → 上 → 右下）、7 個全部が点いたら消す（約 1 秒）。このあいだはスイッチを押しても何も起きない（続けて押したときに、次の決定にならないように） |
| うまくいった（ゴールを保存した、迷路を呼び出せた、走り終わった、ログ出力が終わった） | 7 個全部を 1 秒点ける |
| できなかった（ゴールがスタートの区画を含む、保存した迷路がない、探索で道がなくなった（行き・帰りのどちらでも）、最短走行でゴールへの道がない） | 外側の 4 個（LED1・2・6・7）を速く 5 回点滅させる |

- 点滅の速さ：決定のときの全部の点滅は 0.15 秒ごと、スタート待ちの点滅は 0.25 秒ごと、フェイルセーフの全部の点滅・電池が少ないときの外側の点滅・吸引中の真ん中の点滅は 0.5 秒ごと、「できなかった」は 0.08 秒ごと、ロード中は 1 個 0.15 秒
- 外側の 4 個だけの表示は 3 つあり、点き方で見分ける：点けたまま＝保存中、0.5 秒ごとに点滅し続ける＝電池が少ない、速く 5 回点滅＝できなかった。ただし、モード0 の No.15 を選んでいるときも外側の 4 個が点けたままになる（保存中と同じ見た目。保存は走り終わったときとゴールを入れたときだけなので、場面で見分ける）
- 2026-10-15 に変更：フェイルセーフで止まったときは、全部を点けたままにする代わりに点滅させ、前センサに手をかざす代わりにスイッチで元に戻すようにした。戻るときに「ロード中」を出す
- 入力の読み方：0.01 秒ごとに読む。スイッチは 2 回続けて同じ値を読んだら押した（離した）とみなす（チャタリングを取り除く）。前センサの手は 3 回続けて同じ値を読んだら、かざした（離した）とみなす
- タイヤ 1 段ぶんの回す量は、今は仮に 8192 カウント（タイヤ半回転。`sys/ui.h` の `UI_TIRE_COUNT_PER_STEP`）。実機で決め直す
- モードを選び始めるときに、それまでにタイヤが回った量を忘れる（走っているあいだに回った量で、モードや No. が変わらないように）
- 作ったもの：`sys/ui.c`（LED と入力）、`sys/mode.c`（モードを選んで走らせる）、`sys/goal.c`（ゴールの位置）。PC テスト（`test/test_mode.c`）済み

## 4. モードの割り当て

| モード | 中身 | KOGUMA のモード |
|---|---|---|
| 0 | 探索 | モード0 |
| 1 | 最短走行 | モード1、モード3 No.1〜3 |
| 2 | 探索のターン調整 | モード4 No.2・3・6 |
| 3 | 最短走行のターン調整 | モード5〜10 |
| 4 | 実験用（機体の性能を測る、試しに走らせる。中身は必要に応じて自由に入れ替える） | （ない） |
| 5 | センサ（値の表示と調整） | モード4 No.0、モード3 No.4〜9 |
| 6 | 基本調整 | モード4 No.1、4、5、6、モード6 No.0 |
| 7 | 出力と設定 | モード4 No.7（設定は KOGUMA にはない） |

**どのモードも No.0 は何もしない**（間違えて決定しても何も起きないように。電源を入れた直後はモード0 の No.0）。表にない番号も何もしない。No.0 や表にない番号では、スイッチを押しても決定しない（点滅もしない）。

今 `sys/mode.c` にあるのは、モード0 の No.1〜4（探索）、モード1 の No.1〜5（最短走行。No.1〜3 は小回りだけ、No.4・5 は大回り・斜めあり）、モード2 の No.1・2・4・5（スラローム 90°、U ターン、その場 180° 旋回、壁合わせだけ）、モード3 の No.1〜9（最短走行のターン、斜めの直進のテスト）、モード4 の No.1・3・4〜11（吸引なし・吸引ありの加速度テスト、吸引の力）、モード5 の No.1〜6（センサ値の表示・記録、壁までの距離の表示、壁切れ・柱の見え方テスト）、モード6 の No.1（直進）・No.3（吸引 ON）・No.6（エンコーダの歪みを測る）・No.7（壁に沿って直進）と、モード7 の No.1・2・15（ログ出力、ゴールの位置、迷路呼び出し）。ほかのモードは、中身（最短走行、ターン、センサなど）を作ったときに足す。

### モード0：探索

探索はすべて**吸引なし**のスラローム探索。

| No. | 走り方 | KOGUMA |
|---|---|---|
| 1 | 往復（スタート → ゴール → スタート） | No.1 |
| 2 | 片道（ゴールで止まる） | No.3 |
| 3 | 未知壁探索。ゴールに着いたら、最短経路の上のまだ見ていない壁を見に行く。見に行く壁がなくなったら、止まらずにスタートへ戻る（流れは [KOGUMA_PORTING.md](KOGUMA_PORTING.md) の「ToraNeko の未知壁探索の流れ」） | No.6（KOGUMA は吸引あり） |
| 4 | 未知壁探索＋既知区間加速。No.3 と同じ道を通り、走っているときに、見たことのある区画がまっすぐ 2 区画以上続くところは、まとめて速く走る（最高 600mm/s、2000mm/s²。仮。`config/run_params.h` の KNOWN_*）。曲がるところは No.3 と同じ小回り | No.7（KOGUMA は吸引あり） |

- 探索は、今ある迷路の続きから始める（KOGUMA と同じ）。最初からやり直したいときは、電源を入れ直す
- 作らないもの：吸引ありの探索、全面探索、探索のあとに続けて最短走行を走る（KOGUMA の `SHORTEST`）
- 既知区間加速は No.4 だけ（2026-10-27 に足した。中身は `sys/explore.c` の `try_known_straight()`）。まっすぐ続く区画を数えるだけで、経路（`path_make_known` の path_t、約 4KB）は作らない（RAM が残り少ないため）。PC のテストで、No.3 と同じ道を通り、止まる回数も同じで、見たことのない区画をまとめて走らないことを確かめた（テスト用の迷路 2 つで、まとめて走ったのは 22 区画・37 区画）
- 探索の速さ（KOGUMA は 500mm/s）は実機で決める
- **横壁合わせ**（2026-11-02 に作った。`sys/explore.c`・`ctrl/run.c`。2026-11-03 に実機で、目安を一時的に 40mm にして動きを確かめた）：走っていて、区画の入口で横の壁が `SIDE_TOO_CLOSE_MM`（32mm。区画のまん中は 42mm）より近いとわかったら、動く前にその区画のまん中で止まり、近すぎた側の壁のほうへ 90° 回って前壁合わせ（0.5 秒）をし、元の向きに戻る。左右の位置と向きが直る。そのあとは止まっているので、次の区画へはまん中から発進する（行き先の決め方は変わらない）。どの走り方（No.1〜4）でも、行き・未知壁を見に行くあいだ・帰りで使う。2026-11-03 から**実際に止まって直している**（`config/run_params.h` の `SIDE_ALIGN_ENABLE` が 1）。横の表を測った値にしたあと、探索で毎回 1 回ずつ 30.0〜31.7mm まで近づいていたため。モード7 No.1 の `Search: side wall too close … nearest … (aligned=1)` で、何回直したかがわかる。PC のテスト（`test_maze` の [9] 横壁合わせ）で、ときどき「近すぎる」と答えても、どの走り方も正しく終わり、未知壁探索の最短経路が変わらないことを確かめた
- **壁切れ**（2026-10-28 に作り、2026-11-04 に柱も使えるように作り直した。`ctrl/run.c`・`ctrl/side_edge.c`）：探索で 1 区画まっすぐ進むあいだ、横のセンサで壁の終わり・柱の端を見つけ、そこから区画の境目を求めて、思っていた境目とのずれだけ、その直進の残りを直す（`WALL_EDGE_ENABLE` が 1）。1 区画で 1 回だけ。いちばん近い境目から ±20mm より離れていたら使わない
  - **見つけ方**（`ctrl/side_edge.c`。KOGUMA の `docs/pillar_cut_design.md` と同じ考え方）：1mm 進むごとに左右の値を覚え、直前 15mm のいちばん高い値と、何もないときの値（左 115・右 100）のまん中（半分）を切ったところを、下がる端とする。山が何もないときより 100 以上高いときだけ。山が左 900・右 550 より低ければ「柱だけ」、高ければ「壁の終わり」。区画の境目 ＝ 端 ＋ 34.8mm（壁の終わり）・29.9mm（柱だけ）
  - **値の決め方**：壁切れ・柱の見え方テスト（モード5 No.4〜6）の 6 回のログを、PC で同じ計算に読ませて決めた（`test/test_wall_ctrl.c` の `--replay`）。柱だけの山は低く（右 320〜384、左 544〜564。何もないとき右 74〜150・左 113〜118）、前の「壁あり」のしきい値（右 400・左 650）には届かないので、しきい値ではなく半分で見るようにした。半分で見ると、速さ（300〜1000mm/s）でも左右でも、位置はほとんど変わらなかった（前のしきい値の見つけ方では、左右で 3mm 違っていた）。スタート区画の出口（y=90）の端だけは、ほかより 5mm ずれて見えた（速さ・左右によらない。置き方かスタート区画の壁の形のため）
  - モード7 No.1 に、1 回ごとに `  edge 1: left, pillar, traveled … mm, speed … mm/s, error … mm, lag … mm, used` の形で出す（左右、柱だけか壁の終わりか、走った距離、速さ、いちばん近い境目からのずれ、目標の位置からの遅れ、使えたか）。最短走行の記録も同じ行に出る
  - 前の見つけ方（2026-10-28〜11-04）：入口で壁があった側の値が「壁あり」のしきい値を切ったところで見ていた（区画の入口から左 53.5・右 56.0mm で見つかった）
- **向きを戻す・壁の終わりの見分け**（2026-11-04 に作った。`ctrl/control.c`・`ctrl/wall_ctrl.c`。探索と最短走行の縦横の直進）：柱の見え方テスト（モード5 No.4〜6）で、壁のない区間を 2〜4° 向いたまま走り、壁や柱に当たったので入れた
  - **向きを戻す**：横の壁の補正を入れているのに、左右とも使える壁がないときは、ジャイロの向きを「迷路の向き」（基準の向きから 90° ごと）へ戻す（ずれ × `HEADING_HOLD_GAIN` 20 ×（速さ ÷ 1000）。50mm 進むあいだに戻る。上限 45deg/s）。基準の向きは、走り始めの向き（スタート区画で、お尻を後ろの壁に付けた向き）。探索では、前壁合わせのあと（前の壁で向きを合わせた）と、両側の壁でまん中を平行に走れている状態が 90mm 続いたときに、今の向きを迷路の向きとしてリセットする（作者の案。探索のログで、8 秒走るとジャイロの向きが 2〜3° ずれていたため）。最短走行も同じようにリセットする（はじめは走り始めの向きだけにしたが、2026-11-04 にモード6 No.3 で吸引したまま止めておくと、ジャイロが 1 秒に約 0.14° 流れた〈30 秒で 4°〉ので入れた）。探索の途中で止まって動き出すとき（`control_restart()`）は、基準をそのままにする
  - **壁の終わりの見分け**：壁が終わるところでは、値が下限（左 1000・右 570）を切る前から下がり始め、補正が「壁から遠い」と読んで壁のほうへ曲げていた（柱のテストで 71deg/s）。そこで、5mm 進むあいだに 60 より下がったら壁の終わりとみなし、そこから 15mm はその壁を補正に使わない（`WALL_END_*`）。今ある実機のログに当てはめて決めた（壁の終わり 24 回のすべてで、値が「壁あり」のしきい値を切る 12〜22mm 手前で見分けられ、壁に沿って走っているときに見分けてしまったのは 0.3%）
  - 走行ログでは、向きを戻しているあいだ、`wall` が 0 で、`wall_err` の列に迷路の向きからのずれ [deg]、`wall_p`・`wall_out` に戻す角速度（+ なら右へ）が入る（`logs/README.md`）
- **前壁補正**（2026-10-28 に作った。`ctrl/run.c`。実機はまだ）：走るうちに前後の位置がずれるのを直す。区画の入口で曲がる・止まるとき、その区画に前の壁があれば、前センサで壁までの距離を測り、87mm（入口の辺から前の壁まで）からずれた分だけ、スラロームの前距離と止まる距離を直す（±5mm まで。2026-11-03 に 10 → 5）。2026-11-03 から**実際に直している**（`config/run_params.h` の `FRONT_CORRECTION_ENABLE` が 1、上限 ±5mm）。前の表を測って直したら、探索での平均が +1.6mm になったため。壁までの距離の表（`ctrl/wall_dist.c`）を測って入れ、モード7 No.1 の `Search: front correction … average … min … max …` がおかしくない（数 mm 以内）のを確かめてから 1 にする（2026-11-03 に平均も出すようにした。出す量は、±10mm の上限をかける前の量）。その下に 1 回ごとの量を、探索を始めてから走った距離といっしょに `  front 1: traveled … mm, correction … mm` の形で出す（最初の 40 回まで。壁切れも `  edge 1: …` で同じように出す）。前壁補正は、その次の行に、測ったときの様子も出す（2026-11-03 に足した）：`    FL … FR … mm`（左前・右前のセンサから求めた前の壁までの距離）、`side L … R … mm`（横の壁までの距離）、`overrun … mm`（入口の辺からもう進んでいた距離）、`speed … mm/s`、`yaw … deg`（区画の向きに対する機体の向きのずれ。左回りが +）。止めて測ると 87mm なのに、走っていると +10mm ずれる場所があったので、そのわけを見るため。出してみると、片側に横の壁がないとき、その側の前センサだけが 10〜17mm 遠く読んでいた（向きのずれは 2° 以下）。前の表は横の壁がある状態で測ったので、横の壁から返る光の分が足りないと遠く読む。そこで、左前と右前が `FRONT_CORRECTION_SENSOR_GAP_MM`（6mm）以上違うときは、近いほうだけを使うようにした（2026-11-03。そのログで計算し直すと、平均 +3.7mm → +0.7mm、ばらつき −2〜+10.9mm → −3.8〜+6.5mm）ずれがいつも同じなら表かセンサの読み、走るほど増えるならタイヤの直径か滑り
- 止まるのは、U ターン（止まって、その場で 180° 回って発進する）、未知壁探索で計算するとき、終わり（スタートに戻ったとき、片道でゴールに着いたとき）。終わりは、その区画の真ん中で止まる（スタートでも、後ろの壁に当てる動きはしない）
- 作ったもの：`sys/explore.c`（PC テスト済み。機体を動かす部分の中身はステップ7 で作る）

### モード1：最短走行

- 経路はダイクストラで作る
- **No. は遅い順**。No.1 がいちばん遅く、確実に完走する速さ。大会では 1 → 2 → 3 と上げていく
- 各 No. は速度の表の 1 行で、中身は「ターンの速さ（組 1〜3 のどれか。モード3 のターン調整と同じ組）、直線の最高速、加速度、斜めの加速度、吸引の強さ」
- 「直線の最高速 ＝ ターンの速さ」の行（区間ごとの加減速がない、デバッグ用。KOGUMA のモード3 No.1〜3）も、この表の行として入れる
- 行の数と中身（数値）は実機で決める
- スイッチで決定したときに、スタートからゴールへの道があるかを調べる。なければ「できなかった」を出して、モードを選び直す（走らない）
- ゴールに着いたら止まり、モーターと吸引を止めて「うまくいった」を出す。スタートへは手で戻す（KOGUMA と同じ）
- 走行ログは 8ms おきで 8 秒ぶん。8 秒を超えたら記録をやめるだけで、走行は続ける
- ターンごとに通過速度を変える方式（KOGUMA の TurnV）は、KOGUMA の実機の結果を見てから決める。使うなら、この表に行を足す

**今あるもの**（No.1〜3 は 2026-10-25、No.4・5 は 2026-10-28 に作り、2026-11-04 にターンごとの速さで曲がるようにした。中身は `sys/shortest.c`）

No.1〜3 は、**曲がるところは探索と同じ小回りのスラローム（300mm/s）だけ**にした。直進だけ、No. ごとに速くする。
経路はダイクストラで探し、コストは「この No. の速さで小回りで走る時間」にする（2026-10-27。KOGUMA の #99 の走行時間の表を持ち込んだ。`maze/dijkstra.c`）。小回りのジグザグは 300mm/s のままなので、直進を長く・曲がる回数を少なくした道が選ばれる（壁のない迷路で (7,7) へ行くとき、曲がる回数が 13 回から 1 回になった。PC のテスト）。

| No. | 直進の最高速 | 直進の加速度 |

| 2 | 600mm/s | 2000mm/s² |

- **No.4・5 は大回り・斜めのターンで曲がる**（2026-10-28 に作った。中身は `sys/shortest.c`。**No.4 は 2026-11-04 に実機で走った**：小さなコースで、直進 → 斜め入り右 45°（800mm/s）→ 斜め 1 つ → 斜め出右 45° → 大回り右 90° ×2（3 つとも 693mm/s。ゴールで止まるため）と走り、計算どおりの区画と向きで止まった。ログは `logs/20261104-041704_log.txt`。No.5 は実機はまだ）。ターンの値はモード3 と同じ `config/turn_params.h`（2026-11-04 に 7 つとも実機で合わせた）。**吸引 5.0V で走る**（走り出す前に吸引を 0.5 秒で上げて 0.5 秒待つ。ターンは吸引して合わせたため）。経路は `path_make_shortest()`（大回り・斜め）で、ダイクストラのコストは「直線 ＋ ターン 1 つ」ごとに、その No. の速さとターンの値で本当に走る時間（`dijkstra_set_time_cost_diagonal()`。2026-11-02 に KOGUMA の #100 を持ち込んだ）。ターンの種類ごとの時間の違いまで比べて、走る時間の見積もりが一番短い道を選ぶ（PC のテストで、小さな迷路の道を全部数え上げて確かめた。ランダムな迷路 300 個では、3 つの数のコストで選んだ道より平均 98ms（No.4）・43ms（No.5）速い見積もり）

  - 次のときは、それより遅い速さで直進を終わり、次のターンを、同じ形のまま遅く曲がる（最高角速度 k 倍・角加速度 k² 倍。KOGUMA の最初のターンと同じ考え方）：上げきれないとき（スタートの直後など）、ターンが直進をはさまずに続くとき（ターンのあいだは速さを変えないので、続くターンの遅いほうに合わせる）、その先の短い直進で次の次のターンの速さまで遅くしきれないとき。どこまで遅くしておくかは、経路の終わりまで先を見て決める（`speed_limit_ahead_mm_s()`）
  - ゴールにターンで入って終わるとき（PC で約半分）は、区画のまん中から 6000mm/s² で、40mm 以内で止まる（`SHORTEST_STOP_ACCEL_MM_S2`・`SHORTEST_STOP_DISTANCE_MM`）。止まれる速さは 693mm/s までなので、ゴールに入る最後のターンは 800mm/s のターンでも 693mm/s で曲がる
  - 経路を選ぶダイクストラのコストは、今までどおり、どのターンも 500mm/s（`FAST_TURN_SPEED_MM_S`）で曲がるとして数える（直線の時間が前後のターンの速さで変わり、数えにくいため）
  - PC のテスト（`test_maze` の [10]）：ランダムな迷路で No.4・5 を「仮の機体」で走らせ、どのターンも迷路の形どおりの位置から始まり、直進の速さに無理がなく、ゴールの区画で止まることを確かめた
- 値は `config/run_params.h` の SHORTEST1〜5
- 迷路は RAM のものを使う。探索のあと電源を切ったときは、先にモード7 No.15（迷路呼び出し）で Flash から戻す
- スタート区画では、探索と同じく、お尻を後ろの壁に付けて置く
- 横の壁に沿って走る補正を入れる（斜めの直進のあいだは切る）。吸引は No.4・5 だけ（No.1〜3 は吸引しない）
- **壁切れ**（2026-11-04 に作った。`ctrl/run.c` の `run_fast_straight`。2026-11-04 から**直している**。`FAST_WALL_EDGE_ENABLE` が 1）：縦横の直進で、探索と同じやり方（壁の終わり・柱の端。`ctrl/side_edge.c`）で区画の境目を求め、いちばん近い境目とのずれだけ、直進の残りを直す。1 本の直進で何回でもよい。直進を始める位置が、うしろの区画の境目から何 mm 先か（最初の直進は 35mm、大回り・斜め出のあとは 45mm、小回りのあとは 0mm。`sys/shortest.c` の `straight_start_in_cell_mm()`）から、境目は 90mm ごとにあるとする。スタート区画の出口の境目は使わない（ほかより 5mm ずれて見える）。直したら、そのぶん思っている位置もずらし、2 つ目からは直したあとの位置で比べる（`edge` の行の `error` も、直したあとの位置からのずれ）。同じ境目を左右で見つけたら、2 つ目はずれの半分だけ直して 2 つの平均にする（機体が横にずれたり向きがずれたりすると、左右で逆向きにずれて見えるので打ち消す。2026-11-04 の柱のテストで、まん中より 6mm 右・左へ 3° のとき、同じ境目で左 +4.6mm・右 −0.6mm だった。前は 1 つ目で直した分を差し引かずに、2 つ目でまた直していた）。位置は、目標の位置ではなく、機体が本当にいる位置（目標 − 制御の位置のずれ）で数える（1170mm/s に加速しているとき、機体は目標より 3.4mm 遅れていた）。モード7 No.1 の `edge` の行に出す。はじめは測るだけにして、最短走行 No.4 を 3 回走らせ、ずれが 950〜1170mm/s でも 0〜3mm と小さかったので、直すのを入れた
- 走行ログは 8ms ごと（モード7 No.1 で出す）

**センサ値の表示（No.1）の使い方**

**センサ値の記録（No.2）の使い方**（2026-10-24 に追加。中身は `sys/sensor_record.c`）
- 測りたい区画のまん中に、まっすぐ置く（壁合わせなら、前に壁がある向き）
- スイッチで決定 → 前センサに手をかざして離す。1 秒後に真ん中の 3 個（LED3・4・5）が点き（測っているあいだ、1 秒）、終わると 7 個全部が 1 秒点く（うまくいった）

- ビューア（`tools/viewer.html`）の「メモ」に測った条件（例：`R 64mm`）を書いてから出すと、`logs/` に `日時_sensor_R-64mm.txt` で保存される（[logs/README.md](logs/README.md)）

**壁までの距離の表示（No.3）の使い方**（2026-10-27 に追加。中身は `sys/sensor_view.c`）
- No.1 と同じく、スイッチで決定するとすぐ始まり、もう一度スイッチを押すと終わる
- 0.2 秒ごとに `CAL,左前,左,右,右前,左前mm,左mm,右mm,右前mm` を出す。距離は `ctrl/wall_dist.c` の表で直したもの（区画のまん中で 42mm）
- 表を入れたあと、ものさしで測った距離と同じになるかを確かめるのに使う

**壁までの距離の表の作り方**（2026-10-27 に決めた。表は `ctrl/wall_dist.c`。今入っているのは計算で作った仮の表）

距離は、区画のまん中でどれも 42mm（区画 90mm から壁の厚さ 6mm を引いて 2 で割る）。
- 横（L・R）：機体の中心線から横の壁の表面まで。機体の幅は 40mm（メイン基板。タイヤ・センサホルダも基板の内側）なので、中心線から側面まで 20mm
- 前（FL・FR）：タイヤの軸から前の壁の表面まで。軸から基板の前の端まで 32mm

1. ビューアを開き、「保存先フォルダ」で `logs/` を選んで「接続」する（[logs/README.md](logs/README.md)）
2. 下の距離に機体を置き（壁とまっすぐ平行に）、No.2（センサ値の記録）で測る
3. ビューアの「メモ」に `R 64mm` のように **センサの名前（R・L・F）と距離** を書き、モード7 No.1 で出す。`logs/` に `日時_sensor_R-64mm.txt` で保存される
4. 全部測ったら、`software/main-controller/` で `python3 tools/wall_table.py logs/*_sensor_*.txt` を実行する。出た行を `ctrl/wall_dist.c` の同じ名前の行と置きかえる（同じ距離を何回か測ったときは平均する。距離が遠いのに値が大きいところがあれば「注意」が出る）
5. 書き込んで、No.3 で、ものさしで測った距離と合うかを確かめる

| 測るもの | 置き方 | 距離 [mm] |
|---|---|---|
| 右（`R`） | 左右に壁がある区画で、機体の左の側面を左の壁に付ける（右の壁まで 64mm）。左の壁と機体のあいだに壁の板（6mm）を 1 枚ずつはさむ | 64・58・52・46・40・34・28・22（板 0〜7 枚） |
| 左（`L`） | 右の左右を入れかえる | 同上 |
| 前（`F`。左前と右前を同時に） | 前の壁と、基板の前の端とのすきま g をものさしで測って置く（距離 = 32 + g）。お尻を後ろの壁に付けて板をはさむなら、距離 = 52 − 6 × 枚数 | 32・37・42・52・62・72・87・102・122・142 |

区画の入口で前の壁を見るときの距離は約 87mm なので、そのまわりは正確に測る。

**ゴールの入れ方**（No.2）

ゴールは「左下の区画の位置（x・y）」だけを機体で入れる。大きさは **2×2 で決まり**で、機体では設定しない（コードの定数。違う大きさの大会では、書き換えて書き込み直す）。

1. 7 個全部が 1 回点滅して、x の入力になる
2. 右タイヤを回して値を選ぶ。1 段で 1 ずつ変わる。最初は今のゴールの値
   - 値は LED3〜7 の 2 進数（LED3 = 16、LED4 = 8、LED5 = 4、LED6 = 2、LED7 = 1）
   - 入れられるのは 0〜30（2×2 のゴールが迷路からはみ出さないように）
   - 例：x = 20 → LED3 と LED5 が点く（16 + 4）
3. スイッチを押す。7 個全部が 2 回点滅して、y の入力になる。y も 2 と同じように選ぶ
4. スイッチを押すと、Flash に保存する
   - x と y がどちらも 0 のときは、ゴールがスタートの区画を含むので保存せず、x の入力に戻る

- ゴールは、電源を入れたときに Flash から自動で読む
- 一度も設定していない（Flash にゴールがない）ときは、基準のゴール（x = 7、y = 7。16×16 の迷路の中央）にする。2026-10-24 に作者が決めた（それまでは迷路の中央 (15, 15)、そのあと試走の 4×4 の迷路の (2, 2)）。32×32 の大会では、モード7 No.2 で中央 (15, 15) を入れる

## 5. 迷路の保存と呼び出し

KOGUMA は迷路を RAM にしか持たない（電源を切ると消える）。ToraNeko は Flash にも保存する。

| 場面 | 迷路 |
|---|---|
| 電源を入れたとき | 空。Flash の迷路は自動では読まない |
| モード7 No.15（迷路呼び出し） | Flash の迷路を RAM に戻す（電池を替えたあとに、続きから最短走行・探索をするとき） |
| 探索を始めるとき | RAM の迷路の続きから |
| Flash に保存するとき | ・探索でスタートに戻ったとき<br>・片道でゴールに止まったとき<br>・フェイルセーフで止まったとき（下） |
| 未知壁探索の途中で止まったとき | 保存しない（止まっている時間を延ばさないため。ぶつかったときは、フェイルセーフの保存で残る） |
| 探索で道がなくなって止まったとき（行き・帰りのどちらでも。動きすぎたときも同じ） | 保存しない（壁を読み間違えたかもしれないため。RAM の迷路には残っている。止まる途中でぶつかったときは、フェイルセーフとして扱う） |
| フェイルセーフで止まったとき | 最後に壁を記録した **5 回ぶん**（ふつうは 5 区画。U ターンで同じ区画に 2 回入ると、その区画は 2 回と数える）を、記録する前の状態に戻してから保存する（その走行で初めて入った区画なら「まだ見ていない」に戻る。前の走行で見ていた区画なら、そのときの状態に戻る）。RAM の迷路も同じように戻すので、電源を切らずに探索をやり直しても、ずれた状態で読んだかもしれない壁は使わない |

- 「迷路を消す」操作は作らない。電源を入れ直せば RAM の迷路は空になる。Flash の古い迷路は、次に保存したときに上書きされ、迷路呼び出しを選ばなければ使われない
- Flash に書き込んでいるあいだは、CPU が止まる（STM32F411 は Flash が 1 つで、消しているあいだはプログラムを読めない。128KB の区画を消すのに約 1〜2 秒）。そのため、保存はモーターを止めているときだけにする
- 「最後の 5 区画ぶんを戻す」ために、`maze/maze_map.c` に「壁を記録した区画を、記録する前の状態と一緒に 5 回ぶん覚えておき、戻す」機能を足した（`maze_map_undo_recent_cells`。PC テスト済み）

**保存のしかた**（`sys/flash.c`、`drv/flash_memory.c`。2026-10-15 に作った）

| 項目 | 内容 |
|---|---|
| 保存場所 | Flash のいちばん後ろの 2 つのセクタ（128KB ずつ）。ゴールはセクタ6（0x08040000〜）、迷路はセクタ7（0x08060000〜）。別のセクタなので、片方を保存しても、もう片方は消えない |
| プログラムの大きさ | 保存場所と重ならないように、前の 256KB（セクタ0〜5）に収める（今は約 42KB）。超えたら CI（firmware-build の「サイズ」）が失敗にする |
| 書く中身 | ゴール：目印、x、y、確かめの数（4 語）。迷路：目印、迷路の大きさ、区画ごとに 4 枚の壁の状態と「入ったか」、確かめの数（5123 語、約 20KB） |
| 壊れていないかの確かめ | 「目印」で保存したことがあるかを、「確かめの数」（それまでに書いた数の合計）で途中で電源が切れていないかを調べる。どちらかが合わなければ読まない（迷路の呼び出しは「できなかった」の合図になり、ゴールは基準のゴール (7, 7) になる） |
| 迷路を呼び出すとき | 全部を読んで確かめてから迷路に入れる（途中まで入れて、おかしな迷路になることはない）。「最後に壁を記録した 5 区画」は忘れる（読み込む前の迷路のものなので） |
| プログラムを書き込み直したとき | ふつうに書き込むと、プログラムが入るセクタだけが消されるので、保存した迷路とゴールは残る。書き込みツールで「全部消す（Full chip erase）」をすると消える |

- PC テスト（`test/test_flash.c`）で、Flash の代わりに配列を使って確かめた。本物の Flash に書いて、電源を切っても残るかは、モード7 をファームウェアに入れたとき（タイヤと前センサができたあと）に実機で確かめる
