# KOGUMA からの移植：棚卸しと判断

ToraNeko.Mk3 のファームウェアは、KOGUMA.MkIIl のコード（[../reference/koguma-mkiil/](../reference/koguma-mkiil/)）をベースに作ります。
このファイルは「KOGUMA のどの機能を持ち込み、どれを持ち込まないか」を決めるための表です。コードはここには書きません。

> **参照している KOGUMA のコード**：2026-10-13 に最新版（`2b70f1d3`）へ更新した（それまでは 2026-09-25 の `e456da3`）。
> 最新版ではモード0が「フラグの組み合わせ」（`Maze_Search(flags)`、`SEARCH_SLALOM` / `SUCTION` / `KNOWN` / `DIJKSTRA` / `SHORTEST` など）に書き直され、番号が変わっている。
> 下の C の表の「モード0 No.○」は**古い番号**のまま残している。新しい番号との対応は C の表のすぐ下を参照。

## 方針

- **使っていない機能は持ち込まない。** 呼ばれていない関数、空の分岐、コメントアウトされたコードは移植しない
- **テスト・デバッグ用の機能は、ToraNeko でも使うと決めたものだけ持ち込む**（下の B・C で判断する）
- **パラメータ違いのコピーは 1 つにまとめる**（下の D）
- 実装は README の「実装の進め方」のステップ順に 1 つずつ行う。各ステップで、このファイルの該当行を読み、判断を「確定」にしてから実装する

## 調べ方

`main()` と割り込みの入口（`TIM6_DAC_IRQHandler`、`HAL_ADC_ConvCpltCallback`、`DMA2_Stream0_IRQHandler`）から、関数呼び出しをたどって届くかどうかを調べました。
コメントアウトされた呼び出しは「呼んでいない」として扱っています。対象は `Core/Src/` の自作ファイル（CubeMX の生成コードを除く）です。

| ファイル | 使われている関数 | 使われていない関数 |
|---|---|---|
| `Maze.c` | 27 個（約 1830 行） | 6 個（約 120 行） |
| `Move.c` | 8 個（約 680 行） | 3 個（約 140 行） |
| `motor.c` | 25 個（約 790 行） | 2 個（約 80 行） |
| `PL_encoder.c` | 8 個 | 2 個 |
| `lsm6dsr.c` | 5 個 | 4 個 |
| `UI.c` | 11 個 | 3 個 |
| `PL_sensor.c` | 2 個 | 1 個 |
| `Wallsensor.c` / `Failsafe.c` / `LOG.c` / `PL_timer.c` | すべて | なし |
| `main.c` | `main()` が約 1770 行（モードごとの分岐） | — |

呼ばれていない関数は少なく、全体の約 7% です。量として大きいのは「`main.c` のモード分岐」と「パラメータ違いのコピー」のほうです（C・D）。

| B6 | センサ値の表示（モード4 No.0） | センサ 4 つ（10 回平均）、電池、角速度を printf で出し続ける | 持ち込む。書式も同じにして、ビューアの「センサの値」の流れるグラフをそのまま使う。小数を printf で出せるように、`CMakeLists.txt` のリンクの設定に `-u _printf_float` を足す（今の設定 `nano.specs` のままだと `%f` は何も出ない。Flash が約 10KB 増える） | **確定**：提案どおり |
| B7 | `Wall_search_LED`（壁の有無を LED に表示） | センサ表示のあいだ、4 つの壁の判定（左前・左・右・右前）を専用の LED 4 個に出す | 持ち込む。ToraNeko の LED は 7 個なので、センサ表示のあいだは 7 個のうち 4 個を壁の表示に使う。どの LED を使うかは、基板の並びを見てステップ6で決める | **確定**：提案どおり |

**RAM の見積り**（STM32F411 の RAM は 128KB。KOGUMA の STM32F446 も 128KB だが、迷路が 16×16 なので迷路の処理が小さい）

| 使い道 | 大きさ |
|---|---|
| 迷路の処理（`maze/`、32×32） | 約 60KB（ビルドして測った値） |
| 今あるそのほか（UART の送信バッファ 2KB、HAL、スタック 1KB など） | 約 5KB（ビルドして測った値） |
| これから増えるもの（壁センサ、制御、壁切れのログなど） | 約 10KB（見込み） |
| 走行ログ 1000 行 | 約 34KB |
| 合計 | 約 109KB（残り約 19KB） |

ステップ9でログを作るときに、もう一度ビルドして測り、余っていれば行数を増やす。

### 迷路の大きさとゴール

| 項目 | 決定 |
|---|---|
| 迷路の大きさ | **32×32**（ハーフサイズ）。KOGUMA は 16×16 で、ゴールは中央 2×2 固定 |
| ゴールの位置・大きさ | **位置（x・y）は機体の操作で入れる**（大会ごとに違うため）。**大きさは 2×2 で決まり**（コードの定数）。入れた値は Flash に保存し、電源を入れたときに読む（2026-10-14 に決定。操作は [MODES.md](MODES.md)）。`maze/` はこれまでどおり、ゴールの座標と大きさを引数で受け取る |

### 未知壁探索（`Maze_Unknown_Wall_Scan` と `main.c` の `Maze_Search_Unknown_Walls`）を移したときに変えたこと

最新の KOGUMA（2026-10-13）の流れに合わせた。ダイクストラは止まっているときだけ計算する（走りながらだと KOGUMA で約 9ms、その間に約 1cm 進んでしまう。ToraNeko は 32×32 でクロックも遅いので、もっとかかる見込み）。

| KOGUMA | ToraNeko（`maze/search.c`） |
|---|---|
| 止まって計算する：ゴールに着いたとき、U ターンのとき、目標に着けなかったとき、見に行った壁が実際にあったとき（経路がふさがれた。次の区画の真ん中で止まり、前に壁があれば壁合わせ） | 同じ。計算は `search_plan_unknown_walls()`（重い）。止まっているときに呼ぶ |
| 見に行った壁がなかったときは止まらず、同じ経路で次の未確認の壁へ（`Maze_Unknown_Wall_Scan`） | 同じ。`search_check_unknown_walls()`（軽い）で覚えた経路を見直す |
| 経路がふさがれたかは、見に行った壁だけを調べる（`Maze_Unknown_Wall_Is_Wall`） | 経路の上の**全部の壁**を調べる。見に行く途中で、経路の上の別の壁があるとわかった場合もふさがれたとする（見に行った壁しか調べないと、ふさがれた経路の残りの壁を見て終わり、もっと速い道を見逃すことがある） |
| 見に行く区画は、壁を通り抜けた先（ゴール側）の区画 | 壁のスタート側の区画（その壁の手前）。まだ入ったことのない区画なので、入れば必ずその壁を見られる |
| 経路の未確認の壁がなくなったら、スタートへ戻る | **その場で止まって最短経路を計算してから**、スタートへ戻る（2026-10-13 に決定） |

**ToraNeko の未知壁探索の流れ**（ステップ9の `sys/explore.c` はこの順に書く）

| # | すること | 使う関数 |
|---|---|---|
| 1 | 行き：スタート → ゴール（足立法。既知区間加速は今は使わないので、1 区画ずつ走る） | `search_set_target`、`search_update_step_map`、`search_decide_action` |
| 2 | ゴールで止まって、未知壁探索の経路を計算する | `search_plan_unknown_walls` |
| 3 | 覚えた経路を見直す（`search_check_unknown_walls`）<br>・見ていない壁がある → その手前の区画を目的地にして、壁を見るまで走る（止まらない）<br>・ふさがれた → 次の区画で止まり（前に壁があれば壁合わせ）、計算し直す<br>・途中で U ターンするときは、止まったついでに計算し直す<br>・経路がない（`UNKNOWN_WALL_NO_PLAN`。ゴールへの道が見つからなかった）→ 壁の読み間違いなどの異常。未知壁探索をやめて、止まってスタートへ戻る<br>これを繰り返す | `search_check_unknown_walls`、`search_plan_unknown_walls` |
| 4 | **見に行く壁がなくなったら、その場で止まる。止まってから最短経路を計算する**（ここでは Flash に保存しない。止まっている時間を延ばさないため） | `path_make_shortest` |
| 5 | 帰り：スタートへ戻る（最短走行はスタートから始まるので）。帰りに壁を見ても、4 で計算した最短経路は変わらない。スタートに着いたら、迷路を Flash に保存する | 1 と同じ |

PC テストでは、未知壁探索のあとの最短経路が「全部の壁を知っているときの最短経路」と同じコストになることを、テスト用の迷路 2 つとランダムな迷路 300 個で確かめている（中央 2×2 の迷路：ゴール到着時 196 → 161 = 全部知っているとき 161。止まって計算した回数 16）。

## F. 読んでいて気づいた点（移植時に直す）

### フェイルセーフ（`Failsafe.c`。最新版も 2024 年のまま変わっていない）

KOGUMA は、モーターが動いているあいだ、制御周期の割り込みで毎回調べ、1 回でも条件に当てはまったら止める。止めたときはモーターと吸引を止め（`Motor_Free`）、LED を全部点け、前センサに手をかざすと元に戻る。

| # | KOGUMA | 中身 | 提案 | 判断 |
|---|---|---|---|---|
| F1 | `Failsafe_Motordiff` | 左右のタイヤの速度の差が `motordiff_TH = 100000` を超えたら止める | 持ち込まない。しきい値がタイヤ速度（mm/s）に対して大きすぎて、実際には一度も動いていない | **確定**：提案どおり |
| F2 | `Failsafe_MotorTagetdiff`（前半） | 目標速度より実際の速度が `Vdiff = 2000`mm/s 以上遅い（ぶつかった）ら止める | 持ち込む。ToraNeko の値は実機で決める | **確定**：提案どおり |
| F3 | `Failsafe_MotorTagetdiff`（後半） | 等速で走っているのに速度が 100mm/s 未満（壁を押し続けている）なら止める。「目標速度が 500〜1200mm/s のとき」と探索速度の範囲が直接書かれている | 持ち込む。速度の範囲を書く代わりに、探索の処理（`sys/explore.c`）が「今は探索の直進中」であることをフェイルセーフに知らせる形にする | **確定**：提案どおり |
| F4 | 1 回でも当てはまったら止める | KOGUMA は 1kHz で 1 回 | ToraNeko は 2kHz なので、ノイズ 1 回で止まらないよう、当てはまった状態が決めた時間（例えば 10ms）続いたら止める。時間は実機で決める | **確定**：提案どおり |
| F5 | 止めたときの動き | モーターと吸引を止め、LED を全部点ける。前センサに手をかざすと元に戻る | 同じ | **確定**：提案どおり |
| F6 | 電池の電圧（`main.c`） | 電源を入れたときだけ調べ、下限より低ければ LED を点滅させて止まる | 同じ（下限の値は E の表のとおり 2 セル用に決め直す） | **確定**：提案どおり |
