# 吸引のときのセンサのノイズ(モード3 No.10)

2026-10-12に追加。吸引を回すと壁センサの値にノイズがのる原因を、止まったまま測って分けるテスト。

## 結果(2026-10-18、`logs/20261018-145345_noise.txt`)

**原因は吸引のPWMの電流。FLとLだけに、点灯時にも消灯時にも同じだけのる。** 対策として、ふだんの読み方を「吸引のPWMに合わせて読む」に変えた(`PL_sensor.c`の`sensor_pwm_sync`)。**効果を確かめた**(下の「対策のあと」)。

| 標準偏差(差 = 点灯 − 消灯) | 吸引なし | 吸引35 | 吸引50 | 吸引70 |
|---|---|---|---|---|
| FL | 2.8 | 16.0 | 15.2 | 14.2 |
| L | 1.8 | 6.8 | 6.9 | 7.1 |
| R | 2.2 | 2.7 | 2.6 | 2.7 |
| FR | 2.1 | 3.1 | 3.0 | 3.1 |

- **FLとLだけ**揺れる(FLは約12、Lは約6。点灯時・消灯時とも)。RとFRはほとんど変わらない。FLはADCのch13(PC3)、Lはch11(PC1)。配線か、GNDの戻り道がファンと近いのかもしれない(ハード。大会のあとに見る)
- **消灯時も同じだけ揺れる**ので、LEDの点け方ではなく電気のノイズ。点灯時と消灯時は別のときに読むので、差を取ると揺れが足し合わさって大きくなる(12 → 16)
- **吸引の強さ(35〜70)では変わらない**。吸引を回すかどうかで決まる
- 待ち30us、取り込み56サイクルは**どちらも効かない**
- **PWMの位置で決まっている**。生の値を、読んだときのPWMの位置で並べると、ファンに電流が流れているあいだ(PWMがオン)は約 +10〜+17 高く、切れた瞬間に約 −20〜−27 下がる。オンの長さは吸引の強さ(35・50・70)どおりに伸びた
- この揺れは「LとFLの4msおきの落ち込み」(2026-10-10の走行ログ)とも合う

対策: 点灯時と消灯時を毎回PWMの同じ位置で読めば、両方が同じだけずれるので、差(`g_sensor`)では消える。LEDを切り替える前に、TIM2のカウンタが決まった値(`SENSOR_SYNC_CNT` = 5)になるまで待つ(最大1周期 約20us、1msに3回)。待ってから切り替えるので、LEDを切り替えてから読むまでの時間は今までと同じ。値の大きさ(差の平均)は変わらないはずなので、感度合わせや距離の表は測り直さなくてよいはず(モード3 No.10の「差の平均」で確かめる)。吸引を止めているときは待たない。

- 走っているときは、車輪のモーターのPWM(TIM3、約50kHz)も同じようにのるかもしれない。こちらは今回のテスト(止まったまま)では測っていない

### 対策のあと(2026-10-18、`logs/20261018-150919_noise.txt`)

| 標準偏差(差) | 吸引なし | 吸引35 | 吸引50 | 吸引70 |
|---|---|---|---|---|
| FL PWMに合わせない | 2.6 | 16.0 | 14.5 | 13.1 |
| FL **PWMに合わせて読む** | 2.5 | **2.6** | **2.6** | **4.0** |
| L PWMに合わせない | 1.6 | 5.7 | 5.7 | 5.9 |
| L **PWMに合わせて読む** | 2.1 | **2.2** | **2.3** | **2.8** |

- FLとLのばらつきが、吸引なしとほぼ同じに戻った(FLは吸引70だけ少し残る)
- 差の平均は、PWMに合わせても変わらない(合わせて読む4行のうち、吸引なし〈TIM2が止まっていて待たない〉と吸引ありで同じ)。感度合わせ・距離の表は測り直さなくてよい
- テストのあいだに、FLの差の平均がゆっくり上がっていった(632 → 669)。Lは少し下がった(281 → 268)。読み方ではなく、置いた機体が少し動いたか、温まったためと思われる

### 走っているときのノイズ(2026-10-18、`logs/20261018-151855_log.txt`)

吸引のPWMに合わせたあとでも、モード4 No.1(1000mm/s、吸引70)の走行ログでは、**Lの値が走っているあいだだけ大きく揺れていた**(横センサの値 230前後に対して 38〜395、標準偏差 約73)。Rはきれい(標準偏差 約13)。横の壁までの距離も、左だけ 66〜122mm と跳ねていて、横壁制御がこれを追ってふらついていた。止まって吸引だけ回したとき(モード3 No.10)は揺れないので、**車輪のモーターのPWM(TIM3、50kHz)**がのっていると考えた。

対策(**確かめた**、下の表): 吸引のPWM(TIM2)の周期を、車輪のPWMとぴったり同じ 20us にした(`Suction_Start` の ARR を 100 → 99。今までは 20.2us で少しずれていた)。モーターが動いているときは TIM3 のカウンタに合わせて読む。周期が同じなので、TIM3 に合わせれば吸引のPWMとの位置も毎回同じになる。モード4 No.1をもう一度走らせ、「横センサの値(LPFだけ)」の左が右と同じくらい滑らかになるかで確かめる

| モード4 No.1(走っているところ) | 横センサ 左の標準偏差 | 右 | 左の跳ね(前後9点の中央値から40以上) | 左の距離の標準偏差 | 横壁制御の出力の標準偏差 |
|---|---|---|---|---|---|
| 対策前(`20261018-151855_log.txt`) | 72.8 | 12.8 | 675回 / 1560 | 4.9mm | 2.4 |
| 対策後(`20261018-152950_log.txt`) | 18.7 | 12.1 | 6回 / 1561 | 2.9mm | 1.1 |
| 対策後(`20261018-153311_log.txt`) | 21.8 | 11.7 | 51回 / 1555 | 2.8mm | 1.1 |

左が右とほぼ同じくらいまで落ち着き、横壁制御の出力の振れも半分になった

## 疑っていること

コードと設定から読める範囲での推測。回路図は見ていない。

- **吸引のPWMは約50kHz**。TIM2は 90MHz ÷ 18 ÷ 101 で、周期は約20us。ファンの電流がこの周期でオンとオフを繰り返すので、電池の電圧とGNDが揺れる
- **ADCが1チャンネルを取り込む時間は約0.27us**(3サイクル、ADCクロック11.25MHz)。毎回、PWMの周期のでたらめな位置の一瞬を読む
- **LEDを点けた直後に読んでいる**。点けてから読むまでは、割り込みの処理と1〜2us程度。受光が立ち上がりきる前の値を読んでいると、電源の揺れに敏感になる
- **点灯時と消灯時の値を取るタイミングが十数usずれている**。点灯時はFL・Rがステップ1、L・FRがステップ2(LEDが2組に分かれている)、消灯時はステップ3。PWMの周期と同じくらいずれるので、差を取っても揺れが消えない
- 電気以外では、ファンの振動でセンサの向きが揺れる、吸引で機体が沈む(こちらは揺れではなく平均のずれ)

## 走らせ方

1. 区画の中で、前壁に向けて置く(左右の壁もある区画。前センサも壁を見るように)
2. USBをつなぎ、ビューア(`tools/viewer.html`)で「接続」。「保存先フォルダ」に`logs/`を選んでおく
3. モード3 No.10を選び、前センサに手をかざしてから横センサに手をかざしてスタートする。手を離して待つ(1秒後に測り始める)
4. 約15秒、止まったまま吸引が強くなったり止まったりする。終わるとブザーが鳴る

USBをつながずに走らせたときは、あとで出力(モード4 No.7)を選ぶと、ばらつきの表だけ出る。USBをつなぐとGNDの状態が変わるかもしれないので、両方で比べてもよい。

## 測るもの

次の組み合わせを全部測る。

| | |
|---|---|
| 読み方(2通り) | 吸引のPWMに合わせて読む なし(10-18までの読み方) / あり(今の読み方)。10-18までは「待ち 0/30us × 取り込み 3/56サイクル」の4通りだった |
| 吸引(4通り) | 0(止める) / 35 / 50 / 70 |

組み合わせごとに、吸引を変えてから0.5秒待ち、500回(1msごと)読む。点灯時・消灯時の生のAD値と、その差(点灯 − 消灯。`g_sensor`のもと)について、平均・標準偏差・最小・最大を出す。はじめの100回は、生の値と、読み終えたときの吸引のPWMの位置(TIM2のカウンタ)もそのまま出す。

読み方を変えるのはテストのあいだだけ。終わったらPWMに合わせて読む・待ち0・3サイクルに戻す(`PL_sensor.c`の`g_sensor_pwm_sync`、`g_sensor_settle_us`、`g_sensor_smp_req`)。

## 見かた(ビューア)

| 結果 | 疑うもの |
|---|---|
| 吸引で、消灯時の値も同じくらい揺れる | 電気。GNDの揺れ、ADCの取り込み |
| 吸引で、点灯時の値だけが大きく揺れる | LEDの点け方。電源の揺れ、立ち上がりの途中を読んでいる |
| 待ち30usで減る | LEDを点けた直後の、受光の立ち上がりの途中を読んでいた |
| 取り込み56サイクルで減る | 取り込み時間が短すぎた。ただし56サイクルにすると読むのも約25us遅くなるので、待ちの効果が少し混ざる |
| 差 − 平均を PWM の位置で並べると波の形になる | PWMの電流の揺れを、その瞬間ごとに拾っている。ADCをPWMと同期させれば消せる |
| 差の平均だけが吸引でずれる(ばらつきは増えない) | 機体の沈み込み、電池の電圧が下がってLEDが暗くなる |
| 振動を疑うとき | プロペラを外して同じテストをする。揺れが消えれば振動 |

ビューアの「見立て」は、いちばん強い吸引でのばらつきが吸引なしの1.5倍未満なら「吸引で増えない」とする。そうでなければ、増えた量を比べる。消灯時の増え方が点灯時の半分以上なら電気、そうでなければLEDの点け方と出す。目安なので、表の数字とグラフも見る。

## 結果が出たら

- 効く読み方があれば、ふだんの読み方をそれに変えるか決める。待ちを入れるなら1msのうち約90us、割り込みの中で待つ
- 読み方を変えると値そのもの(差の平均)も変わる。感度合わせ(モード3 No.5)、距離の表(モード3 No.4)、壁切れの値を測り直す
- PWMの位置で変わるなら、ADCをTIM2と同期して始める(毎回同じ位置で読む)ことを考える

## 出力の形

```
#BEGIN NOISE n=500 trace=100 settle_us=30 wait_ms=500 pwm_top=100
stat,読み方,待ち[us],取り込み[サイクル],吸引,センサ,on|off|diff,平均,標準偏差,最小,最大,PWMに合わせるか
batt,読み方,待ち[us],取り込み[サイクル],吸引,平均,標準偏差,最小,最大,PWMに合わせるか      電池のAD値
tr,読み方,吸引,i,点灯FL,点灯R,点灯L,点灯FR,消灯FL,消灯R,消灯L,消灯FR,ph1,ph2,ph3
#END NOISE
```

- センサの並びは`g_sensor`と同じ(FL, R, L, FR)
- `ph1`はFL・Rを点灯して読み終えたとき、`ph2`はL・FR、`ph3`は消灯のときのPWMの位置。0〜`pwm_top`
- 最後の「PWMに合わせるか」(0/1)は 2026-10-18 から。それより前のログにはない
- `tr`の行は、測ったそばから出すときだけある。出力(モード4 No.7)では`trace=0`で、`stat`と`batt`だけ
