# ログの設計(2026-10-12)

ビューア(`tools/viewer.html`)でグラフにできるようになったので、足していくだけだったログを、目的から選び直した。

## 方針

- **どの問いに答えるためのログか**で列を決める
- 列は全部いつも取る(目的ごとに切り替えない)。そのかわり値は int16(単位を決めた整数)で持ち、RAMを減らす
- 1msの割り込みで `G_Log_Div` 回に1回残す。**普段は1(1msおき・2秒)、最短走行は4(4msおき・8秒)**
  - 壁制御のD項やセンサの1回だけの落ち込みは、1msおきでないと見えない(2msおきだと、取る瞬間によって毎回写るか全く写らないかになる)
  - 最短走行は全体の流れを見たいので長さを優先する
- 何の動作中か(`phase`)を残し、ビューアで区間を色分けし、動作ごとに数値をまとめる

## 目的と列

| 目的 | 答えたい問い | 列 |
|---|---|---|
| 共通 | いつ・どこで・何の動作中か | `t`、`x`(走った距離)、`phase`(動作) |
| 速度・加速 | 目標どおりか、電圧が張り付いていないか | `v`、`v_target`、`volt_L`、`volt_R`、`batt` |
| ターン | 角速度は目標に追いつくか、角度は合うか | `w`、`w_target`、`angle` |
| 壁制御(第1) | 中心を走れているか、揺れていないか、どの壁を使ったか、PとDのどちらが暴れるか、センサのノイズ | `dist_L`、`dist_R`(横壁制御が使う距離)、`wall`(使った壁)、`wall_err`、`wall_p`、`wall_d`、`wall_out`、`sensor_L`、`sensor_R`(LPFだけの値) |
| 壁切れ(第2) | (走行ログではなく、壁切れのログ `EDGE` で答える) | |

`phase` の値(`motor.h` の `LOG_PH_*`): 1 直線、2 斜めの直線、3 前距離、4 ターン、5 後距離、6 斜めからの前距離、7 斜めへの後距離、8 その場旋回、9 止まる、10 壁合わせ、0 そのほか。

## 持ち方とRAM

| 列 | 型 | 単位 |
|---|---|---|
| `x` | float | mm |
| `v`、`v_target` | int16 | 1 mm/s |
| `w`、`w_target`、`angle` | int16 | 0.1 deg/s、0.1 deg |
| `dist_L`、`dist_R` | int16 | 0.1 mm |
| `wall_err` | int16 | 0.1 |
| `wall_p`、`wall_d` | int16 | 0.01(`wall_out` は出すときに P+D) |
| `sensor_L`、`sensor_R` | int16 | センサ値そのまま |
| `volt_L`、`volt_R` | int16 | 0.1 |
| `batt` | int16 | 0.01 V |
| `wall`、`phase` | int8 | |

2000行で約68KB(以前は float 10列で80KB)。全体のRAMは約123KBから約115KBに減った。

## 以前のログから変えたこと

- 横センサは5回の移動平均(`g_sensor_av`)から、LPFだけの値(`g_sensor[i][0]`)にした。1回だけの落ち込みが見える
- 横壁制御が実際に使う距離(3回の中央値 → mm)、使った壁、P項・D項を足した
- 角速度は `read_NoiseCut_gyro_z()` を割り込みの中でもう一度呼んでいたのをやめ、`G_Gyro_Z` を使う(もう一度呼ぶと、ジャイロのフィルタの前回値が書き換わっていた)
- 取った行数だけ出す(以前は2000行を全部出していた)

## ほかのログ(変えない)

- 壁切れ(`EDGE`): 柱の端・前距離・後距離の記録。テストでは1mmごとのセンサ値も
- 迷路(`MAZE`)、感度合わせ(`CENTER`)
