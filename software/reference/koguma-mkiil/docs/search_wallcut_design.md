# 探索の直進の壁切れ(設計)

2026-10-18 に作り直した。コードは `motor.c` の `Motor_Search_Straight`、記録は出力(モード4 No.7)の `SCUT`、ビューアの「探索の直進の壁切れ」。

## 目的

探索で、ターンの位置や壁を読む位置がずれないようにする。探索の行動は、区画の境目にある「判断位置」(`Motor_Sula_before` で壁を読む位置)から始まり、ターンの入り方(前距離15mm など)はこの判断位置からの距離で決まっている。前壁があるときは前壁までの距離でターンに入るので正確だが、前壁がないと距離だけなので、判断位置のずれがそのままターンのずれになる。

そこで、1区画まっすぐ進むあいだに次の境目の柱の端を見て、判断位置を直す。

## 最初の版(10-18 の昼)と、うまく行かなかったと考えられる理由

最初の版は、推定した境目にそのまま合わせていた(予想 ± 20mm の推定を使い、± 15mm まで直す)。実機で「うまく行っていなさそう」だった。そのときのログには `SCUT` がなく、何が起きたかは分かっていない。

考えられる理由: **探索のターンは、今の判断位置のまま調整してある**。判断位置が本当の境目からずれていても、ターンの前距離・後距離はそのずれ込みで合っている。最短走行の2000では、ターンのあとの境目は距離から予想した位置より 13〜38mm(平均約22mm)先にあった。探索でも同じなら、最初の版は毎回 +15mm(上限)だけ判断位置を先に動かし、そのぶんターンが遅れて外に膨らむ。

## 作り直した設計

### 基準のずれを測って、ばらつきだけ直す

- dc = 推定した境目 − 距離から予想した境目
- 記録だけで探索を走らせ、dc の中央値を **基準のずれ**(`Search_Edge_Ref`)とする。これが「今のターンの調整が前提にしている判断位置」と本当の境目の差
- 直すときは、`dc − Search_Edge_Ref` だけ直す。ずれの平均は今のまま(ターンの調整を崩さない)で、ターンのたびに変わるばらつきだけを消す

### 3段階(`Search_WallCut`)

| 値 | 動き |
|---|---|
| 0 | 使わない(距離だけ。10-18 より前と同じ) |
| **1(今の既定)** | **記録だけ**。走りは 0 と同じ。予想 ± 60mm(`Search_Rec_Win`)の推定を記録して、基準のずれを測る |
| 2 | 直す。予想 + 基準 ± 20mm(`Search_Edge_Win`)の推定だけ使い、`Search_Corr_Gain` × (dc − 基準)を ± 10mm(`Search_Corr_Max`)まで直す |

### 何もしないところ

- 両側とも壁が続く区画(「壁あり → 壁あり」)は柱の端がないので、どの段階でも何もしない(距離のまま)。曲がる区画の手前では、曲がる側に必ず端があるので、ターンの前は直せる
- 左右の推定が食い違っていた(`EDGE_SRC_DISAGREE`)ときは直さない(記録はする)
- 対象は1区画の直進だけ(スラローム探索 500・吸引探索 1000)。既知区間加速の直線、ターン、Uターンは今までどおり

### 端を探すタイミング

区画の4割(`Search_Look_From`、境目から72mm)を過ぎてから探す。横センサは区画中心で次の境目の柱の真ん中を見る向きなので、次の境目の端は境目から約90〜100mm で見える。4割より前は、前の境目の推定を取り違えないように探さない。

## 記録(`SCUT`)

直進ごとに1行。

```
#BEGIN SCUT n=.. lost=.. mode=.. ref=.. win=.. rec_win=.. max=.. gain=.. look=.. gyro_ofs=.. gyro_sd=.. gyro_rej=.. gyro_torn=.. gyro_try=..
act,prev,x,y,dir,b,dc,corr,src
```

| 列 | 中身 |
|---|---|
| act | 探索を始めてから何番目の行動か |
| prev | 直前の行動(0 直進、1 右ターン、2 Uターン、3 左ターン、5 走り出し)。止まって計算してから向きを変えたときは、進んだ向きの値(0・1・3)になる |
| x, y, dir | いま入った区画と向き(0 北、1 東、2 南、3 西) |
| b | 距離から予想した次の境目(`G_Odo_X`) |
| dc | 推定 − 予想[mm](推定がなければ 0) |
| corr | 直した量[mm] |
| src | 推定(0 見つからず、1 右、2 左、3 左右の平均、+8 左右が合わず片方) |

ビューアは、直前の行動ごとに dc の中央値・ばらつきを表にし、書き写す `Search_Edge_Ref` を出す。

見出しの `gyro_ofs` / `gyro_sd` / `gyro_rej` は、ジャイロのゼロ点[dps]、それを測ったときのばらつき、測ったが使わなかった回数(2026-10-19 から)。`gyro_try` は最近4回の測った値(古い順に「ばらつき:平均」、使わなかったものも)、`gyro_torn` はジャイロの上位と下位がずれかけて読み直した回数(電源を入れてから。2026-10-20 から。`docs/search_stability_research.md` の「段階2を入れた結果」)。同じ出力で `SCUT` の前に、前壁の読み分かれ(`FWALL`)も出る。

## 進め方

1. **記録だけ(`Search_WallCut` = 1)で探索を2回ほど**走らせ、出力する。ターンのある全面迷路がよい
2. ビューアで dc を見る
   - 直前の行動ごとの中央値: ターンのあとがいくつずれているか。走り出しのあと(スタートからの距離で決まる)はほぼ 0 のはず
   - ばらつき: ターンのあとのばらつきが大きいほど、直す効果がある。ばらつきが数mm しかなければ、直さなくてよい
3. ビューアの `Search_Edge_Ref` を書き写し、`Search_WallCut` = 2 にして探索する。ターンのあとで外に膨らまないか、壁に当たらないかを見る。記録で dc − 基準 のばらつきが減っていればよい
4. 悪くなったら 1 か 0 に戻す(大会は 0 か 1 でもよい)

## 先の話

本来は基準のずれを 0(本当の境目に合わせる)にして、スラロームの前距離・後距離を合わせ直すほうがよい。そうすれば、柱の端が見えるたびに判断位置が本当の境目にそろう。大会のあとにする。
