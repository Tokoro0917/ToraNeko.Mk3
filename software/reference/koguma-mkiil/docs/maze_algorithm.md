# 迷路探索アルゴリズム(`Core/Src/Maze.c`)

README から移した(2026-10-12)。

2種類の最短経路計算を実装:

- **`Maze_Shortest_Calculation()`**: セル単位のBFS歩数マップに基づく最短経路。直交移動のみ。
- **`Maze_Dijkstra_Calculation()`**: 半セル(壁境界)単位のグラフ上でSPFA(キューベースのBellman-Ford)を用いたダイクストラ法。斜め走行を使う経路を生成する。境界ノードは「どちら向きに通過しているか」で2つの状態に分けてあり、進めるのは今の向きの先のマスを通る3本の辺(直進1・斜め2)だけ。2026-10-14〜26 は「同じ向きにk歩続けて進む区間」を1回の移動として扱い、区間のコストを `ST_COST`/`DIAG_COST`/`CON_COST`(10-26 からは走行時間の表)で数えていた。2026-10-27 から、コストは最短走行の時間:
  - **コストは最短走行の時間**(既定、`G_Dijk_Time_Cost = 1`。2026-10-27)。状態を「壁の中点 + 通る向き + ここから進む直線の向き」にして、1回の移動を「直線 + ターン1つ」にした。移動のコストは、圧縮(`Shortest_Pass_Compression(_NANAME)`)がそこに作る命令(直線・大回り・斜め入り/出・V90)の時間の合計なので、経路のコストは命令列 `G_Short_Pass_NANAME` の時間になり(`tools/route_time.py` と同じ数え方)、一番速い経路を返す。時間の表(`G_Dijk_Cost`)は、最短走行を始めるときに、走る値(ターンの速度・最高速・加速度・斜めの加速度・ターンの表)から `Maze_Dijkstra_Set_Run()` で作る。スタートから広げ、ゴールの2×2区画に入ったところで終わる。1つ前の状態は持たず、経路をたどるときに「コストが合う1つ前の状態」を探す。詳しくは `docs/dijkstra_cost.md`
  - `G_Dijk_Time_Cost = 0` なら以前のコスト(同じ向きの区間 = 最初の1歩 `ST_COST`/`DIAG_COST` + `CON_COST`×(k−1))

BFS版の経路をたどるときは、ゴール2×2区画の4マス全部を歩数0の起点にして歩数マップを作り直す(探索用の歩数マップはゴールの1マスだけが起点)。スタートからゴールへ行けないときは、どちらも空の経路を返す。

どちらも生成した手順を`Shortest_Pass_Compression()` → `Shortest_Pass_Compression_NANAME()`で圧縮し、コーナーの大廻り・斜め入り/出のパターンに変換してから`Move.c`のモーター制御関数(`Short_NANAME_Move*`/`Short_Dijkstra_Move2000`など)が実行する。

ゴールは迷路中央の2×2区画(標準ルール)。どの面が開口になっているか大会では事前に分からないため、ゴール判定(BFS・ダイクストラとも)は2×2区画を囲む境界のどこから侵入しても「到達」とみなすようになっている。

## 行き止まり潰し(`Maze_DeadEnd_Fill()`)

確認済みの壁だけで出入口が1つ以下になったマスは、入った辺と同じ辺からしか出られないため、そのマス自身が始点/終点でない限り最短経路上に絶対に乗らない。エセ全面探索(ALL_MODE)は未探索マスを片端から目標にするので、放っておくとこうした袋小路のポケットにも寄り道してしまう。

`Maze_DeadEnd_Fill()`はそういうマスを`G_MAZE_Closed[][]`に記録し、**連鎖させる**。1マス閉じるとそのマスは隣にとって「出口」として数えられなくなるので、袋小路の通路が根元まで一気に潰れる。`Maze_Gool_Setting()`は閉鎖マスを全面探索の目標候補から外す。

呼び出しは`Maze_Wall_Update()`の4方向分岐、`Maze_Step_Calculate()`の直前。

安全側に倒すための作りが要点:

| 方針 | 理由 |
|---|---|
| `G_Maze_Row`/`G_Maze_Column`(実測の壁マップ)を書き換えない | マップの保存・表示・ダイクストラは今まで通り真の壁だけを見る |
| 閉鎖情報を歩数マップBFSの通行判定に使わない。使うのは目標選定だけ | 誤って閉じても起きるのは「そのマスを探索しない」だけ。経路が塞がる/帰還できなくなる経路が構造的に存在しない |
| 毎回ゼロから再計算(ステートレス) | 誤った閉鎖が累積しない。探索用⇔帰還用のゴール切り替えにも自動追従 |
| 未確認の壁は「開いている」とみなす | 既知の壁 ⊆ 真の壁 なので、探索途中の部分知識では完全知識より必ず閉鎖数が少なくなる |
| スタート・現在の目標・ゴール2×2区画は閉じない | スタートは初期状態で3枚壁。守らないと即座に潰れて帰還できなくなる |

`G_DeadEnd_Fill_Enable`を`0`にすると実行時に無効化でき、従来動作に戻る。閉鎖したマス数は`g_deadend_closed_count`で確認できる(`Maze_Mapping()`内にコメントアウト済みの可視化用printfあり)。

副次的な効果として、壁で完全に囲まれた到達不能マスは出入口0で必ず閉鎖されるため、ALL_MODEが通常の「未探索マス数が0」の経路でクリーンに終了するようになった(従来は「自分のマスがMAX_STEPのまま」を検出するフォールバック頼みだった。フォールバック自体は保険として残してある)。

## 迷路サイズ

`Core/Inc/Define.h`の`MAZE_SIZE`(既定16)を書き換えるだけで16×16⇔32×32を切り替えられる。壁ビット幅・ノード配列サイズ・キュー容量・ゴール座標は全てこの値から自動的に導出される。

16×16の現在のビルド(Debug、arm-none-eabi-gccでの確認)はFlash約147KB、RAM(data+bss)約113KB/128KB(2026-10-27。ダイクストラの状態を3倍にして約+5KB、走行ログを2000→1600サンプルにして約−14KB)。32×32はこのままではRAMに入らない。ダイクストラの作業領域は16×16で約14KB(コスト・キュー各約7KB)、32×32で約80KB(コストをuint32にする)。32×32を実際に有効化する場合は、`Core/Src/LOG.c`の`LOG_MAX`(現在1600。走行ログは約58KB)を含めたRAM予算の再確認が必要。

## 迷路の出力(`Maze_Debug_Dump()`、出力 モード4 No.7 の中)

保存済みの迷路(`Maze_Save()`した壁と見た壁)と、最短走行と同じ手順で作った命令列をシリアルに出す。モーターは動かさない。迷路はRAMにしかないので、**探索のあと電源を切らずに**モード4 No.7を選び、前センサに手をかざしてから横センサに手をかざす(2026-10-12 まではモード3 No.0)。

出力の中身:

- `MAZE_DUMP_BEGIN`〜`MAZE_DUMP_END`: PCで読み込む用の16進(`ROW`/`COL`=壁、`LROW`/`LCOL`=見たかどうか)
- 地図: `---`/`|`=壁、空白=壁なし、` . `/`:`=未確認(最短走行では壁として扱う)、`S`=スタート、`G`=ゴール
- `BFS_PASS`/`BFS_NANAME`、`DIJK_PASS`/`DIJK_NANAME`: 最短走行の命令列(圧縮前/斜め圧縮後)
- `TIME_MAX_US`: 電源を入れてからの各計算の最大時間[us](壁の記録+歩数マップ、既知区間の経路生成、歩数マップ、ダイクストラ)。探索中は計算のあいだも機体が進むので、長いとその分だけ直線が伸びる

ターミナルの出力をファイルに保存して、PCで確かめる:

```sh
gcc -std=c11 -Wall -I Core/Inc -o test_shortpath test/test_shortpath.c Core/Src/Maze.c Core/Src/ShortParam.c -lm
./test_shortpath --dump log.txt
```

PCで同じ命令列が作られるか(`robot output: same as PC`)と、その命令列が壁に突っ込まずゴールに止まるか(`path: OK`)を表示する。最後に止まるところは、ゴールに入った区画の1つ奥の区画の中心(命令列が境目で終わるときは1.5区画、区画の中心で終わるときは1区画進む。`Move.c` の `Short_Goal_X`、2026-10-20)。スタートからゴールへ行けない場合は`no path`になる。
