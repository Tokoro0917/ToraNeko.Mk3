# 柱の壁切れの設計(2026-10-12)

今後は**柱を壁切れとして使う**。この文書は、そのための検出・位置の求め方・走行での使い方・確かめ方をまとめたもの。実装はこの文書に合わせ、変えたらここも直す。

## 1. 目的

- 区画の境目の柱を、**速度・左右・会場の明るさ・壁の有無によらず、同じ精度で**見つける
- 見つけた柱から「区画の境目がどこにあるか」を求め、ターンの前距離・後距離をそこに合わせる
- 見つからないときや、おかしな値のときは、エンコーダの距離だけで走る(今と同じ)

目標の精度: 境目の位置のばらつき ±2mm 以内(500〜2400mm/s、左右とも)。

## 2. 前提(寸法とセンサ)

- クラシック: 区画180mm、柱・壁の厚さ12mm。区画中心から横壁の表面まで84mm
- 横センサは L・R の2つ。値は1msごと(`pl_callback_getSensor`)
- **横センサの向き**: 区画中心にいるとき、ちょうど柱の真ん中(前に90mm、横に84mm)を見るように作ってある。真横から前へ約47°(tanθ ≈ 90/84 ≈ 1.07)の、ほぼ斜めのセンサ。したがって:
  - 柱の端は、機体の中心が柱より約90mm手前(区画中心のあたり)にいるときに見える。境目に着く前にわかるので、前距離には余裕がある
  - **横のずれに敏感**: 機体が壁に y[mm] 寄ると、その側で見える位置が約 1.07 × y 変わる(反対側は逆向き)
  - **向きのずれにもっと敏感**: 機体が1°傾くと、見える位置が約3.1mm変わる(84mm ÷ cos²47° × 1°。左右で逆向き)
- **センサ値ができる時刻**: 1msの割り込み(TIM6)がAD変換を始め、割り込みが終わったあと、DMAの割り込みの中で4段階を続けて変換し、最後に`g_sensor`を作る(優先度はどちらも0なので、DMA側はTIM6が終わるまで待つ)。つまり**TIM6の中で読む`g_sensor`は、約1ms前に測った値**
- `g_sensor`には0.85/0.15のLPF(遅れ約0.2ms)、`g_sensor_av`は5回の移動平均(遅れ約2ms)、3回の中央値は遅れ約1ms

## 3. 柱のところでセンサ値がどう変わるか

ある側(左か右)の、境目の前の区間 A と後の区間 B に壁があるかどうかで4通り。

| # | A(手前) | B(先) | センサ値の変化 | 見えるもの |
|---|---|---|---|---|
| 1 | 壁 | 壁 | 変わらない(柱は壁と面一) | **なし** |
| 2 | 壁 | なし | 高 → 低 | 柱の後ろの端で**下がる** |
| 3 | なし | なし | 低 → 高 → 低(山) | 柱の前の端で上がり、**後ろの端で下がる** |
| 4 | なし | 壁 | 低 → 高 | 柱の前の端で**上がる** |

- 2と3は、どちらも「柱の後ろの端で下がる」。従来の壁切れ(壁の終わり)は2のこと
- 4は下がるところがない。上がるところ(柱の前の端)から、柱の幅だけずらして境目を求める
- 1は何も見えない。距離だけで走る
- ターンの前距離では、曲がる側(内側)は境目の先が必ず開いているので、2か3になり、**下がる端が必ずある**

## 4. 全体の形

```
[DMA割り込み] センサ値ができたら、その時点の走行距離といっしょに記録する
      ↓  (1mmごとの履歴、左右それぞれ)
[検出] 下がる端・上がる端を見つけ、「端の位置」をイベントとして出す
      ↓
[境目の推定] 端の位置 + 種類ごとのずれ(実測で決める)= 境目の位置
      ↓  (左右の両方にあれば平均)
[走行] 前距離: 境目 + A まで走ってからターン / 後距離: 境目 + B で終わる
       見つからなければ距離だけで走る
```

今の実装(2026-10-12の1回目)との違い:

| | 今 | この設計 |
|---|---|---|
| 判定 | 走行の関数が待ちながら「5mmで40以上減ったか」を見る | 割り込みで端を見つけ、**位置**を記録する。走行の関数は記録された位置を使う |
| 端の位置 | 閾値を超えた瞬間(信号の大きさで位置が変わる) | 信号の大きさに左右されない位置(下記) |
| センサ値の距離 | TIM6の時点の距離(約1ms分ずれる) | センサ値を測った時点の距離 |
| 前距離 | Xの半分から待ち始め、それより前の柱は見逃す | 少し前までさかのぼって、記録された端を使える |
| 上がる端(#4) | 使わない | 使う(2段目) |
| 左右 | 曲がる側だけ(前距離) | 両方に端があれば平均(向きのずれが打ち消される) |

## 5. 検出の中身

### 5.1 記録

- DMA割り込みで`g_sensor`を作った直後に、そのときの`G_Odo_X`(動作ごとに0に戻らない走行距離)といっしょに`DistHist`(1mmごと、32mm分)に入れる。測った時刻と距離のずれがなくなる
- 入れる値は3回の中央値(1回だけの落ち込みを消す)。中央値の遅れ(約1ms)の分は、距離を `速度 × 1ms` だけ戻して入れる

### 5.2 下がる端(#2・#3): 直前の最大値の半分を切ったところ

- 直前 `EDGE_HIGH_LEN`(30mm)の最大値 `H` を追う
- `H` が `EDGE_MIN_HIGH`(壁・柱があるとみなす最小値)を超えていて、値が `H / 2` を下回った位置を端とする(UKMARSと同じ考え方)。1mmの点の間は直線で補間して、1mmより細かく求める
- 会場が明るくても暗くても、壁から少し離れていても、`H`も同じ割合で変わるので、**半分を切る位置はほとんど変わらない**(固定の閾値80だと変わる)
- 下がりきるのを待たないので、遅れなく出せる
- いちど出したら、値が `H / 2` より十分上(壁か柱が見えている)に戻るまで次を出さない(柱1本で2回出さない)

### 5.3 上がる端(#4): 変化がいちばん急なところ(2段目)

- `Pillar_Len`(5mm)進む間の増え方 `D` が `EDGE_MIN_RISE` を超えたら追い始め、`D` がいちばん大きかった位置を端とする(`D` が最大の8割まで下がったら出す)
- 上がりきる高さは前もってわからないので、半分を切る方法は使えない。変化が最も急な位置も、信号の大きさに左右されない
- 出すのがピークの少し後になるが、上がる端は柱の前の端で、境目より手前なので間に合う

### 5.4 端を出さないとき

- ターン中と、ターンが終わってから `EDGE_MASK_AFTER_TURN`(10mm)進むまで(機体が回るとセンサが壁をなめて、柱でない変化が出る)
- 角速度が `EDGE_MAX_W`(例えば 100deg/s)を超えているとき(横壁制御で大きく向きを直しているときなど)
- 前壁がすぐ近いとき(横センサが前の壁や柱を見ることがある。`Wall_Flont_Av()` が大きいとき)
- 斜め走行中(この設計の対象外。従来どおり)

## 6. 境目の位置の求め方

`境目 = 端の位置 + ずれ`。ずれは、左右・端の種類ごとに実測で決める(モード3 No.6〜9)。

| ずれの原因 | 大きさ | 扱い |
|---|---|---|
| センサの向き・取り付け位置 | 一定 | 実測のずれに含める |
| 遅れ(センサ値を測る時刻) | 速度 × 遅れ | 測った時点の距離で記録するのでなくなる |
| 中央値の遅れ | 速度 × 1ms(2400で2.4mm) | 記録するときに戻す |
| 機体の横のずれ y | 1.07 × y(5mm寄ると約5mm) | 左右で逆向きにずれるので、**左右の平均で打ち消す**。片側だけのときは、端の直前に測った横壁までの距離 d で `(d − 84) × EDGE_TAN` だけ直す(d はその側の壁、なければ反対側の壁から 168 − d) |
| 機体の向きのずれ ψ | 1°で約3.1mm | 左右で逆向きにずれるので、**左右の平均で打ち消す**。片側だけのときは直せない(横壁制御で向きをそろえておく)。誤差としていちばん大きいので、実機で確かめる |
| 会場の明るさ | 半分を切る位置は変わりにくい | 実測で確かめる |
| タイヤの滑り | 端から曲がり始めまで(数十mm)の距離の誤差 | 短いので小さい |

`EDGE_TAN`(初期値 1.07)は、機体を横に±5mmずらして置いたときの、見える位置の変わり方から実測で決める(取り付け位置で90/84から少しずれるため)。

左右の両方に端があり、2つの境目が `EDGE_PAIR_TOL`(15mm)以内なら平均を使う。離れすぎていたら、`H`(信号の大きさ)が大きいほう、つまり壁に近く確かなほうを使う。

## 7. 走行での使い方

### 7.0 ターンと柱の位置の関係

最短走行の経路(`test/test_shortpath.c` の半区画のモデル)では、ターンは**区画中心から始まり、区画中心で終わる**。前距離はその区画中心から曲がり始めまで、後距離は曲がり終わりから次の区画中心まで。横センサは区画中心で柱の真ん中を見る向きなので、

- 前距離の始め(区画中心)の前の境目(+90mm)の柱の後ろの端は、**前距離の始めの約6mm先**で見える
- 後ろの境目(−90mm)の柱の端は、その約180mm手前(前の区間)で見えている
- ターンの終わり(区画中心)の次の境目の柱の端も、ターンの終わりの約6mm先。角速度が下がりきる前後なので、後距離のうちに確かに見つけるのは難しい

従来の前距離は「Xの半分から待つ」ので、X が短い(2400で3〜25mm)と、壁の終わりはもう過ぎていて待たずに進んでいたはず(実機のログ〈出力(モード4 No.7)〉で確かめる)。

### 7.1 前距離(`Cut_ST_Pillar`)

区画中心から X で曲がり始める、というもともとの意味を変えずに、区画中心の位置(エンコーダの距離)を境目の実測で直す。

- 前の境目の推定 c が `区画中心 + 90 ± Edge_Win`(20mm)にあれば、曲がり始め = `c + X − 90`
- なければ後ろの境目の推定が `区画中心 − 90 ± Edge_Win` にあれば、曲がり始め = `c + 90 + X`
- どちらもなければ `区画中心 + X`(距離だけ)
- 推定は毎回取り直す(後ろの境目で決めていても、前の境目が見えたらそちらに替える)
- ターンをはさんだ推定は使わない(角速度で履歴を空にした位置より前のもの)
- エンコーダの距離がぴったり合っていれば、従来の「壁切れが働かないとき」と同じ位置で曲がる。今合わせてある X をそのまま使える

### 7.2 後距離(`Cut_END`)

柱を使うときは X だけ走る(7.0のとおり、後距離のうちに使える柱がない)。曲がり終わりの位置のずれは、次の前距離が前・後ろの境目で直す。

従来の後距離は「壁が終わったら終わる」なので、もし従来の後距離が X より早く壁切れしていたなら、柱に替えると後距離が長くなる。実機のログ(`end_cut`)で、従来の後距離がどこで終わっているかを先に確かめる。

### 7.3 使わないところ(この設計の範囲外)

- 斜めの壁切れ(`Cut_*_NA`): 従来どおり(あとで一本化する)
- 探索: 従来どおり(最短で確かめてから広げる)

## 9. 確かめ方

### PC(CIで毎回)

- `DistHist`: どの速度でも決まった距離前の値が取れる(できている)
- 検出: 4通り(#1〜#4)の形の信号を、速度500〜3000、信号の大きさ0.6〜1.4倍、ノイズ(1回だけの落ち込み)入りで作り、
  - 端の位置のばらつきが ±1mm 以内
  - #1では何も出ない、#3で下がる端が1回だけ出る
  - 1回だけの落ち込みで端が出ない
- 境目の推定: 左右に逆向きのずれ(向き・横のずれ)を入れて、平均で打ち消されること

### 実機

1. モード3 No.6〜9: 横の壁の並びを#2・#3・#4がそろうように置き、速度を変えて境目からのずれを出す。ずれを決め、ばらつきが ±2mm に入るかを見る
2. 機体を横に5mmずらして置く、少し斜めに置く: 片側のずれと、左右の平均の効き方を見る
3. 最短走行で使う: 前距離・後距離の反応位置をログに出し、従来と並べる

## 11. 決めていないこと

- 横センサの向きは、区画中心で柱の真ん中を見る設計(約47°)とわかった(2026-10-12)。`EDGE_TAN` は実測で詰める
- 前距離では曲がる側の片側だけのことが多く、向きのずれ(1°で約3mm)は直せない。実機で、ターン前の向きのずれがどれくらいかを見る

## 付録: テストとログの形(README から移した、2026-10-12)

**壁切れの位置のテスト**(モード3 No.6〜9)。スタート位置(後ろの壁に付けて置く)から4区画まっすぐ走り(加速度20000、No.6: 500 吸引なし、No.7: 1000、No.8: 2000、No.9: 2400、No.7〜9は吸引70)、柱の端と、比べるための閾値の判定を、残す。結果は出力(モード4 No.7)で出す(走らせたあと、電源を切らずに)。出力の形(数値は例):

```
---- EDGE  Off(R)=84.0/84.0 Off(L)=84.0/84.0 Tan=1.07 MinHigh=90 HighLen=30 Pillar=0 Fast=0
fall,R,wall,30.2,114.6,231,border=114,c-border=0.6
th,R,av,38.9,x-border=-75.1
```

- `sig`: 横センサの値(3回の中央値)。1mmごと、`sig,x,右,左`。ビューアでグラフにする
- `fall`: 柱の下がる端。側、種類(`wall` 壁の終わり / `pillar` 柱だけ)、端の位置、境目の推定 c、その前の最大値 H、c と区画の境目(114 + 180k)の差。**c-border が0になるように`Edge_Off`を直す**(左右・種類ごとに、速度を変えても同じになるかを見る)
- `th`: 比べるためだけの閾値の判定(`av` 従来の`g_sensor_av < Cut_*`、`med` 3回の中央値`< Cut_*`)
- x はどれも走り出しからの距離[mm]

**壁切れのログ**(出力はモード4 No.7)。最短走行(モード1、モード0 No.8〜10)のあいだ、柱の端(`fall`)、前距離の始め(`st`)と曲がり始め(`st_cut`、どの推定を使ったか)、従来の壁切れで反応した位置(`cut`)、後距離の始めと終わり(`end` / `end_cut`)を残す(160行まで)。列の意味は`Wallsensor.c`の`Edge_Log_Print()`。従来の壁切れのまま走らせても、前距離の始めと曲がり始め(`st` / `st_cut`、src 16 は壁切れした、32 は曲がる側に壁がなく距離だけ)を同じ形で残すので、従来の前距離が「区画中心 + X」からどれだけずれて曲がり始めているか、柱のときと並べて比べられる
