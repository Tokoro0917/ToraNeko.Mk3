## 動かし方

ロータリーエンコーダの`Encorder_mode_out()`(モード)と`Encorder_number_out()`(ナンバー)の組み合わせで動作を選ぶ。どちらも0〜15。

1. モードとナンバーを選ぶ
2. **左前センサに手をかざす**(`Sensor_Enter()`、FLが1400超)
3. ブザーのあと**左右の横センサに手をかざす**(`Sensor_Start()`、L+Rが2000超)とスタート

走行が終わると`Encorder_count_reset()`でモード0・No.0に戻る。迷路とログはRAMにしか残らないので、**出力するまで電源を切らない**。

## 大会での流れ

1. **会場に着いたら感度合わせ**(モード3 No.5): 区画中心で値を測る → 出た行(`WallDist_Scale`と各しきい値)を書き写す → ビルドし直す(手順は「会場ごとの感度合わせ」)
2. 探索(モード0)
3. 最短走行(モード1)
4. 走らせるたびに、電源を切らずに出力(モード4 No.7)し、ビューアで保存する(迷路とログはRAMにしか残らない。リセットや電源断で消える)

気をつけること:

- `Core/Inc/Define.h`の`MAZE_GOOL_X/Y`は標準ゴール(迷路中央2×2、`MAZE_SIZE/2-1`)。ベンチテストでスタート近くにゴールを置きたいときだけ一時的に書き換え、**書き換えたままコミットしないこと。** 行き止まり潰しのゴール保護もこの定数から導出している。出力(モード4 No.7)の迷路の図の`G`でゴールの位置を確認できる。
- `Move.c`の`Short_Dijkstra_Move2000()`終端の旋回角度(180°→270°)の調整は、手元で作業中ならリポジトリには未反映。
- **フェイルセーフで止まったとき**(2026-10-27 から、ToraNeko.Mk3 と同じ戻り方): モーターと吸引が止まり、LED が全部 0.5 秒ごとに点滅する。**スイッチ(基板の S2)を押す**と、「ロード中」(LED1〜8 を順に点ける、約1秒)を出してモード0・No.0 に戻る。電源は切らなくてよい。探索中なら、最後に壁を書いた5区画を書く前の状態に戻して保存してあるので、そのまま探索のやり直しや最短走行ができる
- ゴールは1マス(`MAZE_GOOL_X/Y`、16×16で(7,7))を目指して探索する。標準の中央2×2のゴールなら必ず入れるが、そのマスに行けない迷路では探索の逃げ道がなく、前の壁に向かって進んでしまう(全面探索には「どこにも行けなければスタートへ戻る」逃げ道がある)。

### モード0: 大会用(探索走行)

往路(スタート→ゴール)のあと、片道ならゴールで止まり、それ以外はスタートへ戻る。区間の終わりごとに`Maze_Save()`する。No.8〜10はスタートに戻ったあと2秒待って最短走行(モード1 No.5と同じ: ダイクストラ、コーナー2000、直線6000mm/s、加速20000)まで走る。中身は`main.c`の`Maze_Search(flags)`で、番号ごとに`SEARCH_*`の組み合わせを指定している。

| No | 走り方 | 復路 | `SEARCH_*` |
|---|---|---|---|
| 0 | (何もしない) | | |
| 1 | スラローム探索(500mm/s、吸引なし) | 往復 | `SLALOM` |
| 2 | スラローム探索 | 往復、復路で**エセ全面探索** | `SLALOM \| ALL` |
| 3 | スラローム探索 | **片道**(ゴールで止まる) | `SLALOM \| ONEWAY` |
| 4 | 吸引探索(1000mm/s、吸引あり) | 往復 | `SUCTION` |
| 5 | 吸引探索 | 往復、復路で**エセ全面探索** | `SUCTION \| ALL` |
| 6 | 吸引探索 | ゴール後に**ダイクストラ誘導の未知壁探索**、終わったらスタートへ | `SUCTION \| DIJKSTRA` |
| 7 | 吸引探索+**既知区間加速** | No.6と同じ | `SUCTION \| DIJKSTRA \| KNOWN` |
| 8 | スラローム探索 | 往復 → **最短** | `SLALOM \| SHORTEST` |
| 9 | 吸引探索 | 往復 → **最短** | `SUCTION \| SHORTEST` |
| 10 | 吸引探索+**既知区間加速** | No.6と同じ → **最短** | `SUCTION \| DIJKSTRA \| KNOWN \| SHORTEST` |
| 11 | 吸引探索+**既知区間加速** | No.10 の最短を**4回**。最短のあとは、ゴールから No.6 と同じ探索をしながらスタートへ帰り、2秒待って次の最短。4回目のあともスタートへ帰り、帰れたら曲を流す(自律賞の条件) | `SUCTION \| DIJKSTRA \| KNOWN \| SHORTEST \| REPEAT` |
| 12 | 吸引探索+**既知区間を斜めで**(お遊び、ブランチ `claude/play-known-naname`) | No.10 と同じで、既知区間を斜めの命令列(`Known_Pass_NANAME`)で走る。斜め入り・斜め出・V90 は `G_Turn1000`(モード5で調整)、斜めの直線は最大3000・加速度10000 | `SUCTION \| DIJKSTRA \| KNOWN \| KNOWN_NANAME \| SHORTEST` |

片道(No.3)はゴール区画に入ったところで、Uターンのときと同じ減速(70mm)で止まる。

No.11(2026-10-20)は、最短走行のあと、止まった区画と向きを命令列から求め(`Maze.c`の`Short_Pass_End_Cell()`。ゴールに入った区画の1つ奥の区画の中心で、最後に180°向きを変えている)、そこからスタートへ帰る(`main.c`の`Maze_Return_From_Goal()`)。帰りは、保存した迷路に戻してから(最短走行は見ていない壁を壁で埋めるため)、ダイクストラ誘導の未知壁探索をして、見る壁がなくなったらスタートへ帰る。止まった区画のほかの壁は見ていないことがあるので、最初は来た区画へまっすぐ出る。最短がゴールまで走れなかったときや、帰る途中でフェイルセーフが働いたときは、そこでやめる。走行ログ・壁切れのログは、最後に走った最短のものが残る。

既知区間加速(`Robot_Maze_Pass_Action()`)は、次の区画が探索済みなら、未探索の区画の手前までを`Known_Pass_Generation()`でまとめて経路にし、直線を最大4000mm/sで走る。

ダイクストラ誘導(No.6/No.7/No.10)は往路でゴールに着いたあと、スタート→ゴールのダイクストラ経路上に残っている未確認の壁を、今いる位置から直接見に行く(`Maze_Unknown_Wall_Scan()`)。経路の計算は、未確認の壁を「通れる」として行う。計算し直すのは、ゴールに着いた直後、Uターンしたとき、**見に行った壁が実際にあった・経路のほかの壁が「壁あり」とわかった(経路がふさがれた)とき**、**見に行く途中で目標の区画に行けなくなったとき**(2026-10-27)だけで、どれも**機体が区画の中央で止まっているあいだに**計算する。ゴールに着いた直後と、壁があったときは、次の区画の中央で止まり、前に壁があれば壁合わせをしてから計算し、進む向きを決めて発進する(`Robot_Maze_Stop_And_Go()`)。Uターンでは止まっているあいだに計算し(`G_Stop_Hook`)、行き止まりでなければ計算した結果で進む向きを決め直す。見に行った壁がなかった(通れた)ときは、ダイクストラは計算し直さず、止まらずに同じ経路で次の未確認の壁を探す。経路上の未知壁がなくなったらスタートへ帰る。このとき、その経路の壁はすべて確認済みなので、それが本当の最短経路になる。経路は、よく使う最短走行の値の組(`ShortParam.c` の `G_Short_Run_Set`。今は 2000 と 2400)ごとに、それぞれの時間で一番速いものを求め、全部の組の経路の壁を確認する(2026-10-27。1つ目の組の経路を見終わったら、止まって次の組の経路を計算する)。なので、どの組で最短を走っても本当の最短経路になる。

エセ全面探索(`Maze_Unkown_ALL_ModeSet()`)が有効なのは**No.2・No.5だけ**。したがって**行き止まり潰しが走行に影響するのもこの2つだけ**(`Maze_DeadEnd_Fill()`自体は常に計算されるが、結果を使う`Maze_Gool_Setting()`の分岐がALL_MODE時にしか通らないため)。

探索のアルゴリズム(BFS・ダイクストラ、行き止まり潰し)は`docs/maze_algorithm.md`。

## 出力とビューア

### 出力(モード4 No.7)

RAMに残っているデータを全部、迷路 → 壁切れのログ → 走行ログ → センサのノイズ の順に出す(ないものは出さない。最後に`#DONE`)。出力のモードはこれひとつ(感度合わせ・距離の表は、そのモードで出し続ける)。

| データ | いつ残るか | 中身 |
|---|---|---|
| 迷路(`MAZE`) | 探索の区間の終わりごと(`Maze_Save()`) | 壁・見た壁、最短走行の命令列(BFS・ダイクストラ)、計算時間。詳しくは`docs/maze_algorithm.md`の「迷路の出力」 |
| 壁切れのログ(`EDGE`) | 最短走行のあいだ、壁切れのテスト(モード3 No.6〜9) | 柱の端、前距離・後距離の始めと終わり、テストでは1mmごとの横センサの値。詳しくは`docs/pillar_cut_design.md`の付録 |

### ビューア(`tools/viewer.html`)

ロボットのUART出力を、そのままグラフ・表・迷路にするページ。Tera Termはいらない。ネットも使わない(外から何も読み込まないので、会場でも使える)。

1. ロボットをUSBシリアルでつなぎ、`tools/viewer.html`をWindowsのChrome(かEdge)で開く(ダブルクリック)。Tera Termは閉じておく(同じCOMポートは1つしか開けない)
2. 「接続」を押してCOMポートを選ぶ(115200)。届いた文字は下のコンソールに出る
3. 「保存先フォルダ」でリポジトリの`logs/`を選ぶと、届いたデータを1つずつファイル(`日時_種類.txt`)にして自動で保存する。そのファイルをコミットすれば、Claudeは元のデータをそのまま読める
4. ロボットでモード4 No.7(出力)を選ぶと、残っているデータ(迷路・壁切れ・走行ログ)が全部届き、左の一覧に種類ごとに増えて、自動で表示される

届く途中でデータが抜けると、迷路がまるごと届かなかったり、走行ログの行が足りなくなったりする。2026-10-18 までは、受け取りの入れ物が255バイトしかなく、グラフを描いているあいだにあふれていた(1MBにして、届き終わってから描くようにした)。迷路が届かなかったときはコンソールに、走行ログの行が足りないときはそのログの上に出るので、もう一度出力する。

## 壁センサ・横壁制御・壁切れ

### 壁センサの距離変換(`Core/Src/WallDistance.c`)

壁センサの値は距離に比例しない(近いほど急に大きくなる)。センサ値の差をそのまま制御に使うと、壁に近いときはゲインが効きすぎ、遠いときは効かなくなる。また左右のセンサで感度が違うため、`(L - 220) - (R - 200)`は単位の違う数どうしの引き算になる。`WallDist_mm(sensor, value)`はセンサ値を距離[mm]に変換する(表引き+直線補間)。

距離の定義: 横センサは機体の中心線から横壁の表面まで、前センサは機体の中心から前壁の表面まで。区画中心ではどちらも84mm。

**横(L/R)は実測値**(2026-10-06)。機体の側面を反対側の壁につけ、壁の板(12mm)を n 枚はさんで、測る側の壁までを 133 − 12n mm(n = 0〜8、37〜133mm)にして測った(区画の内のり168mm、機体の幅70mm)。区画中心付近(85mm)で L=237、R=201。**前(FL/FR)も実測値**。お尻を後ろの壁につけ、板を n 枚はさんで前の壁までを 108 − 12n mm(n = -8〜4、60〜204mm。n が負はお尻を後ろの壁から離した)にして測った(全長120mm、中心からお尻まで60mm)。区画中心(84mm)で FL=645、FR=627。60mmより近い点はまだ測っていない(表の範囲外は端の値になる)。

#### 距離の表を作り直すとき(モード3 No.4)

1. モード3 No.4を選び、前センサに手をかざしてから横センサに手をかざしてスタートする
2. 約0.2秒ごとに`CAL,FL,L,R,FR,FL_mm,L_mm,R_mm,FR_mm`の形式でシリアル出力される(センサ値は100回平均、`_mm`は現在の表で変換した距離)
3. 横センサ: 機体を横にずらし、壁までの距離を44, 54, …, 124mmに合わせてL/Rの値を記録する
4. 前センサ: 前壁までの距離を34, 44, …, 174mmに合わせてFL/FRの値を記録する
5. `WallDistance.c`の表に書き写し、`test/test_walldist.c`を実行して表の並びが正しいか確認する
6. もう一度モード3 No.4で、`_mm`の列が実際の距離と一致するか確認する

手で機体を動かすとエンコーダのモード選択が変わるが、キャリブレーション中はループの中にいるので影響しない。終了はリセット。

#### 会場ごとの感度合わせ(モード3 No.5)

会場では壁の反射の強さ(塗装)が変わり、センサ値が全部の距離でほぼ同じ割合で変わる。表は作り直さず、区画中心で1回測った倍率で合わせる。

1. モード3 No.5を選び、前センサに手をかざしてから横センサに手をかざしてスタートする
2. 機体を区画中心に置き、前・左・右に壁がある状態にする(スタート区画なら、後ろの壁のほうを向けて置く)
3. 約1秒ごとに、500回平均した値と、書き写す行がシリアルに出る
   - `WallDistance.c`の`WallDist_Scale`(倍率 = 測った値 / 表の区画中心の値。距離変換はセンサ値をこれで割ってから表を引く)
   - `Wallsensor.c`の`Wall_L`/`Wall_R`/`FlontWall_Distance`(区画中心の値そのもの)と`Wall_threshold`
   - `Move.c`の`ALIGN_FRONT_MIN`、`motor.c`の`Cut_R`/`Cut_L`/`Cut_R_NA`/`Cut_L_NA`
4. 出た行を手で書き写してビルドし直す。終了はリセット

閾値は「倍率1のときの値 × 倍率」で出す。基準の値は`Wall_Center_Calibration()`の中にある(2回目以降も、書き写したあとの値ではなく基準の値に掛ける)。閾値の基準を変えたら、ここも直す。

### 横壁制御(`Wallsensor.c`、`G_WallCtrl_Use_mm`)

`Wallsensor.c`の`G_WallCtrl_Use_mm`を1にすると、横壁制御(`Wall_Control_Update()`、1msに1回)の誤差を`(84 - 距離)`[mm]で計算する。2026-10-07から既定は1。0に戻すと従来のセンサ値版(`センサ値 - Wall_L/Wall_R`)になる。モード4 No.8はこの走行のあいだだけセンサ値版で走る。

距離版の中身:

- 横センサは直近3回の中央値を使う(1回だけの落ち込みを消す)
- 壁まで`WallCtrl_mm_MaxDist`(120mm)以内の壁だけを使う
- 片側の誤差を±`WallCtrl_mm_ErrMax`(20mm)で頭打ちにする。片側の壁だけのときは誤差を2倍にする
- `WallCtrl_mm_StableLen`(10mm)進む間に距離が`WallCtrl_mm_StableTH`(15mm)以上変わった壁は、壁の見え始め・消えかけとして使わない(何ms前と比べるかは速度から決める)
- ゲイン`Kp_mm`/`Kd_mm`(0.30 / 0.06)は、区画中心付近(約6[値/mm])でセンサ値版の`Kp`/`Kd`(0.05 / 0.01)と同じ効き。センサ値版は壁から離れると効きが弱くなるが、距離版は弱くならない
- ゲインは速度/500倍(2000以上は4倍)。下限`WallCtrl_mm_GainMin`は今は0(下限なし)
- 壁の有無が切り替わった瞬間はD項を出さない

ほかの人のやり方との比較は`docs/wall_research.md`。

### 壁切れ(`motor.c`)

ターンの前後の直線(前距離・後距離)を、横の壁や柱を基準にして合わせる。`main.c`の`Short_WallCut_Pillar`(既定1)で、最短走行の間だけ方法を切り替える(`G_WallCut_Pillar`)。探索中と斜めの壁切れ(`Cut_L_NA`/`Cut_R_NA`、150)はいつも従来どおり。

**従来**(`Short_WallCut_Pillar` = 0)。横センサ(`g_sensor_av`)が`Cut_L`/`Cut_R`(80)を下回ったところを壁の終わりとみなす。
- 前距離: Xの半分まで走り、曲がる側に壁があれば下回るまで待ってから、残りX/2を走る
- 後距離: 壁があった側が下回ったら終わる。Xは最大
- `g_sensor_av`は5回の移動平均で約2ms遅れ、反応する位置が速度×2ms後ろにずれる(1000で2mm、2400で4.8mm)。`G_WallCut_Fast`を1にすると3回の中央値(遅れ約1ms)で判定する(斜めも)。既定は0。1にすると壁切れの位置が変わるので、前距離・後距離を合わせ直す

**柱**(`Short_WallCut_Pillar` = 1、2026-10-12、設計は`docs/pillar_cut_design.md`)。今後はこちらに一本化する(斜めは決まっていないことが多いので、いまは従来どおり)。
- 横センサは区画中心で柱の真ん中を見る向き(真横から約47°)なので、柱の後ろの端は、機体の中心が境目より約84mm手前のときに見える
- センサ値ができるたび(DMA割り込み、`pl_callback_getSensor`)に`Wall_Edge_Sample()`が、その時点の走行距離(`G_Odo_X`、動作ごとに0に戻らない)といっしょに左右の値(3回の中央値)を1mmごとの履歴(`DistHist.c`)に残す。中央値とLPFの遅れ(`Edge_Lag_S` = 1.2ms)の分は距離を戻す
- **下がる端**(壁の終わりも、柱だけの山も): 直前30mm(`Edge_High_Len`)の最大値の半分を切った位置(`PillarEdge.c`)。会場の明るさや壁との距離で信号の大きさが変わっても、位置はほとんど変わらない。PCのモデルでは、速度300〜3000・信号の大きさ0.6〜1.4倍で位置のばらつきが約0.2mm(従来の閾値80では16.5mm)
- **境目の推定** c = 端の位置 + `Edge_Off`(左右・種類ごと、モード3 No.6〜9で実測。2026-10-18 に 87〜99)+ `Edge_V_K` × 速度(0.0060。速いほど手前に見えるのを戻す)+ 横のずれの補正 `(壁までの距離 − 84) × Edge_Tan`(0.58。CADでセンサが真横から前へ30°)。壁までの距離はその側の壁、なければ反対側の壁から求める
- 角速度が150deg/s(`Edge_Max_W`)を超えたら(ターン中など)履歴を空にし、それより前の推定は使わない
- 前距離: 前距離の始め(区画中心)から X で曲がり始めるのを、境目の実測で直す。前の境目(区画中心+90 ± `Edge_Win` 20mm)の推定があれば「境目 + X − 90」、なければ後ろの境目(区画中心−90)で「境目 + 90 + X」、どちらもなければ距離だけ。左右の両方に推定があれば平均する(向きのずれ1°で約3mmが左右で逆に出るので打ち消される)
- 後距離: Xだけ走る(ターンのあと、次の境目の柱はターンの終わりのすぐ後に見えるので後距離では使えない。その境目は次の前距離で使う)
- 上がる端(手前に壁がなく先に壁がある所)はまだ使わない(設計の段階2)

壁切れのテスト(モード3 No.6〜9)の走らせ方と、壁切れのログの形は`docs/pillar_cut_design.md`の付録。

## ビルド・ハードウェア・ディレクトリ

- MCU: STM32F446RE(Cortex-M4, Flash 512KB, RAM 128KB)。今のビルドで RAM 約113KB / Flash 約147KB(Debug、-O0。2026-10-27 に PC で同じ設定でリンクして確認)
- 開発環境: STM32CubeIDE 1.14.0。本フォルダをワークスペースにインポートしてビルドする

```
Core/Src, Core/Inc   本体ファームウェア
Drivers/             STM32 HAL / CMSIS
KOGUMA.MkII/          旧バージョン一式(参考用に同梱)
test/                ホスト(PC)上で走るテスト(迷路・距離変換・速度計画・距離ごとの履歴・柱の端)
tools/               ビューア(UART出力をグラフ・表・迷路にする)、ログからノイズと性能の限界を出すスクリプト(limits.py)
logs/                ビューアで保存したロボットの出力
sim/                 PC上の探索シミュレータとブラウザ用の可視化
docs/                調べたことのメモ(他の人のターン速度の決め方、壁制御・壁切れのやり方など)
.github/workflows/   CI設定
*.ioc                STM32CubeMX設定
STM32F446RETX_*.ld   リンカスクリプト
```

`Debug/`(ビルド成果物)とホストテストの実行ファイルは`.gitignore`で除外している。
